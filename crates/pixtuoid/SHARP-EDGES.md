# pixtuoid binary — known sharp edges

Indexed one line each in [`CLAUDE.md`](CLAUDE.md). These look like bugs and are deliberate design — read the entry before "fixing" one. An entry is the edge + the WHY + one authority pointer; adjudication history lives in the cited issue/PR.

- **Windows focus-jump borrows the foreground thread's input state; the two better-known bypasses are refused on purpose.** `AttachThreadInput` + one retry; the verdict is `GetForegroundWindow`, not the BOOL (a flash-only outcome sets no error); the detach rides `Drop`. Refused: synthetic-ALT `SendInput` (injects a real keypress into whatever app the user is typing in) and `FreeConsole` (detaches the console the TUI draws into). A miss is a silent no-op — escalation is a UX question, not a louder bypass (`focus/windows.rs`).

- **`--graphics off` conflates protocol capability with the cutaway's profile decision — deliberately.** Nothing paints the cutaway yet (`render_cutaway`'s only caller is `examples/cutaway_snapshot`), so splitting now would ship a `--profile` flag no painter reads; the two come apart when a second surface adopts the cutaway.

- **Capacity GROWTH strands an already-allocated overflow agent; render conservatively, count completely.** `AgentSlot.floor_idx` freezes at allocation while `floor_of` recomputes from current capacities, so growth can render an agent on NO floor (pinned by `build_floor_scene_skips_agent_below_grown_offset`) while `board::per_floor_counts` still counts it — the footer must never lose a blocked agent. Don't harmonize either side; the real fix is a `DeskPlacement` minted at allocation (a cross-crate reshape).

- **Terminal cell aspect drives sprite design.** The half-block ▀ technique assumes ~1:2 cell aspect; sprites larger than ~16×16 px break on taller-cell terminals. Bundled character sprites max at 8×12 px. A PNG-loader experiment hit this wall and was deleted in favor of hand-drawn `.sprite` art.

- **`--max-desks` applies to `run` only, and floating's capacity publish is `store`, not `fetch_max` — don't harmonize.** `run`: capacity auto-computes from terminal size; an explicit cap clamps via `fetch_max` (grow-only — an over-seed strands agents). Floating: seeds and republishes from exact window-pixel size, so a shrink LOWERS capacity; the publish + resize memo live in `offscreen.rs`, not coverage-excluded `window.rs`. Pinned by `a_shrink_lowers_the_published_capacity_it_is_store_not_fetch_max` (#827).

- **The floating pipeline boots in `resumed`, not `floating::run` — the seed needs the PHYSICAL `window.inner_size()`.** Config size is LOGICAL (HiDPI-stable) and buffer size is not monotone in scale factor, so no logical-side seed is sound (#803). The hook socket binds after window+surface creation (a hook in that gap exits 0 — the shim contract); `resumed` sets `live` before `self.window` and `redraw` guards window-first — don't reorder. Pinned by `the_boot_seed_tracks_the_physical_window_not_the_logical_config`.

- **Re-install is a SEMANTIC no-op, and backups APPEND their suffix.** `MergeOutcome.changed` compares parsed configs, not bytes; `backup_once` appends `.pixtuoid.bak` (`with_extension` would truncate a multi-dot name). Pinned in `install/io.rs`.

- **Daemon presence is ANNOUNCE-only; don't "fix" invisibility with a poll.** `gateway_start` fires once per gateway process start, so a gateway pixtuoid never heard stays unseen until its next forwarded hook (`apply_presence` creates on any proof-of-life delta). The panel, `connect`, and `verify_schema` already say so; announcing at plugin `register` was deferred (needs its own double-announce guard).

- **Connecting OpenClaw is not the last step — a RUNNING gateway must restart.** Upstream marks `plugins.load` reload-kind `restart`, so `connect` legitimately succeeds with no lobster. The step rides ONE field, `Target.post_install_hint` (compile-forced; deliberately NOT in `--json`, whose `message` means failure). Pinned by `only_openclaw_declares_a_post_install_step_and_it_names_the_restart`.

- **`connect openclaw` binds ONE state dir, and that install covers EVERY gateway of that profile (1:N, verified live).** Upstream resolves the dir WITHOUT reading `OPENCLAW_PROFILE`, so a gateway under another profile shows no lobster with a GREEN doctor. Auto-discovering `~/.openclaw-*` was deferred (N surprise config writes into dirs the user never named); profile-aware install starts with a read-only doctor note, not a widened write.

- **OpenClaw's config is JSON5, so pixtuoid REFUSES to rewrite a non-strict document instead of "fixing" it.** A `serde_json` round-trip silently deletes a human's comments — so would adding a JSON5 parser, and so does upstream's own `openclaw config patch` (re-serializes strict; measured and rejected — don't re-propose without re-measuring). Id matching is trim-only CASE-SENSITIVE (a case-insensitive compare regressed both ways); an empty `allow: []` means NO restriction, so uninstall never writes one (`uninstall_never_empties_the_allowlist_even_when_every_entry_is_ours`). `preserve_order` is enabled on THIS crate only (WHY in `Cargo.toml`).

- **`disconnect` reserves `Err` for the persist-abort and folds hook-removal failure into `Ok` — never a silent clean "disconnected".** One core (`crate::sources::{connect,disconnect}`), two presenters (Sources panel, CLI) that both surface the folded outcome; the CLI honors an explicit id without the panel's `NoCli` guard (automation pre-provisioning).

- **`OutcomeRow` `{id, outcome, message?}` is a PUBLISHED wire — no flag-day edits.** Installed Raycast copies parse the wire independently of the binary's version (the folded→split change broke users); any further change needs a version handshake. Drift gate: the `just gen-contract` chain; pinned in `sources_cli.rs` + `change_outcome_wire_tokens_are_stable`.

- **Code-artifact targets: install writes ⊆ verify checks, CONTENT included (#387).** The artifact that BAKES the shim path is read back and stat'd (`check_shim_binary`) — a moved `pixtuoid-hook` leaves the plugin loading while every forward dies silently (#332). Any new code-shipping path in `install_target` must gain a matching `verify_target` check; the generic pins loop every `extra_artifacts` target.

- **A decoder arm is NOT evidence the event arrives — `*_EVENTS` in `install/<cli>.rs` is the other half of the wire, and nothing links the two.** A decode arm without its install-list row rendered a permission-parked CC session as WORKING indefinitely. Adding a decode arm obliges checking the install list, and only a captured gated run settles which list is wrong (`fixtures/claude-code/permission-recorded` + that tree's `README.md`).

- **`doctor`'s `<cli> --version` probes are GATED on presence — several CLIs bootstrap their state dir on ANY invocation.** An unconditional sweep manufactured the presence it reports (and defeated HOME-isolated e2e). `doctor::may_probe_version` gates on connected-or-detected; a never-run CLI honestly reports `version unknown`. Pinned by `run_never_spawns_a_version_probe_for_a_cli_it_has_no_evidence_of`.
