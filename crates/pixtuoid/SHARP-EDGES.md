# pixtuoid binary — known sharp edges

Indexed one line each in [`CLAUDE.md`](CLAUDE.md). These look like bugs and are deliberate design — read the entry before "fixing" one. An entry states the edge, the WHY, and where the authority lives (the pinning test, the in-code comment, or the issue); the full adjudication history is in the cited issue/PR, not here.

- **Windows focus-jump borrows the foreground thread's input state, and the two BETTER-KNOWN bypasses are refused on purpose.** A console TUI doesn't own its host window, so `SetForegroundWindow` flashes the taskbar instead; `focus::windows::activate_os` attaches to the foreground thread (`AttachThreadInput`) for one retry. Three details are load-bearing: the message-queue prime (`ensure_message_queue`) is not optional, the verdict is `GetForegroundWindow` not the BOOL (the call sets no error on the flash-only outcome), and the detach rides `Drop`. A doubly-refused jump can leave the target restored-but-unfocused (the minimized-restore runs first, deliberately). Refused: the synthetic-ALT `SendInput` trick injects a real global keypress into whatever app the user is typing in, and `FreeConsole` detaches the console the TUI draws into. The ONE failure rule: a miss is a silent no-op — if that proves insufficient, the next step is the UX question, not a louder bypass.

- **`--graphics off` answers TWO questions at once, and the second one is the cutaway's — but it is a `doctor` flag, and NOTHING paints the cutaway yet.** `render_cutaway`'s only caller is `examples/cutaway_snapshot`, so `graphics::resolve` reports a CAPABILITY ("not yet wired to `run`"). The conflation (protocol availability vs profile decision) is left deliberately — splitting now would ship a `--profile` flag no painter reads; the two come apart the moment a second surface adopts the cutaway, and the scale ARITHMETIC is already split correctly (`RenderScale::fit` in the engine).

- **Capacity GROWTH strands an already-allocated overflow agent, and the HUD keeps counting it — render-conservatively, count-completely.** `AgentSlot.floor_idx` is frozen at allocation while `floor_of`/`floor_range` recompute from CURRENT capacities, so growth can leave an agent rendering on NO floor (pinned by `build_floor_scene_skips_agent_below_grown_offset`) while `board::per_floor_counts` deliberately still counts it (the footer's cross-floor alarm must never lose a blocked agent). Don't "harmonize" either side — deriving render from `floor_of` is the capacity-driven migration #36 closed, and deriving counts from render breaks `board.rs`'s rule. The real fix is a single `DeskPlacement` minted at allocation — a cross-crate reshape, not a local patch.

- **Terminal cell aspect drives sprite design.** The half-block ▀ technique assumes ~1:2 cell aspect; sprites larger than ~16×16 px break on taller-cell terminals. Bundled character sprites max at 8×12 px. A PNG-loader experiment hit this wall and was deleted in favor of hand-drawn `.sprite` art.

- **`--max-desks` has no hard default, applies to `run` only, and floating's capacity publish is `store`, not `fetch_max` — don't harmonize.** Absent, per-floor capacity is auto-computed from terminal size (`FALLBACK_DESKS = 16` only headless/on error); an explicit-cap boot path must clamp to real layout capacity (`fetch_max` only grows, an over-seed strands agents). The floating window seeds and republishes capacity purely from window-pixel size through the shared `offscreen` helpers (seed provably can't drift from redraw — `the_first_redraws_publish_agrees_with_the_boot_seed`); a shrink LOWERS capacity because the window size is exact and authoritative. The publish + its resize memo live in `offscreen.rs`, NOT `window.rs` — that file is excluded from coverage AND mutants, so a decision left there is measured by nothing. Pinned by `a_shrink_lowers_the_published_capacity_it_is_store_not_fetch_max` + `the_resize_memo_publishes_on_a_change_and_skips_a_repeat` (#827).

- **The floating pipeline boots in `resumed`, NOT in `floating::run` — the seed needs the PHYSICAL `window.inner_size()`.** The `[floating]` config size is LOGICAL by design (HiDPI-stable persistence), and buffer size is NOT monotone in scale factor, so no conservative logical-side seed is sound (#803: a 2× display seeded 80 desks where the real buffer holds 30). `FloatingApp` holds a `PipelineBoot` until `resumed`; the hook socket binds after window+surface creation (a hook in that gap exits 0 silently — the shim's documented contract — in exchange for no orphaned socket on window failure). `resumed` sets `live` before `self.window` and `redraw` guards window-first — don't reorder. The unit is enforced by the TYPE (`PhysicalSize<u32>`) because the glue is coverage-excluded. Pinned by `the_boot_seed_tracks_the_physical_window_not_the_logical_config` + `an_unlayoutable_window_seeds_zero_not_a_fallback`.

- **Re-install is a SEMANTIC no-op, and backups APPEND their suffix.** `MergeOutcome.changed` compares the parsed/merged config, not bytes — a second connect skips the write and preserves hand-formatting; `backup_once` appends `.pixtuoid.bak` (deliberately not `with_extension`, which would truncate a multi-dot name). Pinned in `install/io.rs`.

- **Daemon presence is ANNOUNCE-only — a gateway pixtuoid never heard announce is invisible until its next activity; don't "fix" with a poll.** `gateway_start` fires once per gateway process start, so connecting under a running gateway (or restarting pixtuoid) starts lobster-less until the next forwarded hook (`apply_presence` creates on any proof-of-life delta); only an IDLE gateway stays unseen. The panel says `no gateway seen`, `connect` prints the restart step, `verify_schema` notes the reload mode. Announcing at plugin `register` was DEFERRED (needs its own double-announce guard); a liveness poll is a different mechanism than this push-only lane.

- **Connecting OpenClaw is NOT the last step — a RUNNING gateway must restart, and the presenters say so.** Upstream marks `plugins.load` reload-kind `restart` (verified in the shipped bundle), so `connect` legitimately succeeds with no lobster. The step rides ONE field, `Target.post_install_hint` (compile-forced across targets), so the panel and CLI can't disagree; deliberately NOT in `--json` (that envelope's `message` means FAILURE — the frozen Raycast contract). Pinned by `only_openclaw_declares_a_post_install_step_and_it_names_the_restart`.

- **`connect openclaw` binds ONE OpenClaw state dir — and that ONE install covers EVERY gateway of that profile (profile↔gateway is 1:N, verified live).** `gateway run --port` lets one state dir host N concurrent gateways off a single connect (which is also why profile can't be the mascot identity — the core guide's daemon-identity edge). A named profile is a second `connect` via `OPENCLAW_STATE_DIR` — upstream resolves the dir WITHOUT reading `OPENCLAW_PROFILE` (verified live; the CLI flag selects it), so a gateway under another profile shows no lobster with a GREEN doctor (which verified the dir it DID bind). Auto-discovering `~/.openclaw-*` was DEFERRED: N surprise config writes into dirs the user never pointed us at, many vestigial. If profile-aware install is ever wanted, start with a read-only doctor note, not a widened write.

- **OpenClaw's config is JSON5, so pixtuoid REFUSES to rewrite a non-strict document instead of "fixing" it.** Our `serde_json` round-trip would silently delete a human's comments, so `openclaw::parse_for_merge` bails with the reason + OpenClaw's own commands, and `verify_schema` reports it as a soft NOTE (a hard verdict was advice that could not succeed). Id matching is trim-only CASE-SENSITIVE (a case-insensitive compare regressed both ways — re-read `normalizePluginIdWithLookup` before changing); an empty `allow: []` is NO restriction, so uninstall NEVER writes an empty list (`uninstall_never_empties_the_allowlist_even_when_every_entry_is_ours` — the guard tests the RESULT, not the input length). Delegating the write to `openclaw config patch` was measured and rejected: upstream's own writer re-serializes strict, dropping comments, while costing a subprocess + PATH dependency — don't re-propose without re-measuring that round-trip. Don't add a JSON5 parser either: that trades a loud refusal for silent comment loss (`merge_refuses_a_json5_document_instead_of_dropping_its_comments` — its fixture is VALID JSON5 on purpose). `serde_json`'s `preserve_order` is enabled on THIS crate only (WHY in `Cargo.toml`); `Value` equality stays order-independent, so semantic-no-op detection is unaffected.

- **Two surfaces bind a source, ONE core.** `crate::sources::{connect,disconnect}` (persist + install/uninstall + rollback) is the single seam with two presenters: the in-TUI Sources panel (adds the one live-gate line) and the scriptable CLI (persist-only by design — the live set is in-process). `disconnect` reserves `Err` for the persist-abort and folds hook-removal failure into the `Ok` outcome, surfaced by BOTH presenters — never a silent clean "disconnected". The CLI honors an explicit id without the panel's `NoCli` guard (pre-provisioning for automation). The status model lives in `sources`, so the `--json` contract doesn't depend on the painter.

- **`OutcomeRow` is `{id, outcome, message?}` — and the wire is PUBLISHED; no more flag-day edits.** The split from the folded `failed: <msg>` string shipped while the store copy of the Raycast extension still parsed the old form (the publish marker predates the split) — the break reached users. Installed copies parse the wire independently of the binary's version, so any further wire change needs a version handshake or a deliberately coupled migration. The drift gate is the schema→codegen chain (`just gen-contract` → committed schema golden → generated TS → `tsc`); bytes and token set pinned in `sources_cli.rs` + `change_outcome_wire_tokens_are_stable`.

- **Code-artifact targets: install writes ⊆ verify checks, CONTENT included (#387).** opencode's TS plugin IS its `config_path` (schema check covers it); OpenClaw's JS plugin is `extra_artifacts` (stat'd — a missing artifact is a HARD doctor break, #332). Existence is not enough for the artifact that BAKES the shim path: a moved `pixtuoid-hook` leaves the plugin loading while every forward dies silently (observed live) — so the baked path is read back and stat'd through the same `check_shim_binary`. Any NEW code-shipping path in `install_target` MUST gain a matching `verify_target` check; both generic pins loop every `extra_artifacts` target, so a future one is auto-guarded.

- **A decoder arm is NOT evidence the event arrives — `*_EVENTS` in `install/<cli>.rs` is the other half of the wire, and nothing links the two.** CC's permission gate is `PermissionRequest`; `decoder.rs` has handled that arm since Codex needed it, while `install/claude.rs` registered four tool events without it, so a CC session parked on a permission prompt rendered as WORKING, indefinitely. No test could see it: the fixtures were composed from the same belief, and the composed one invented a `Notification` reading "Claude needs your permission to use Bash" that upstream never sends — the only `Notification` a gated run fires is the idle "Claude is waiting for your input". So adding a decode arm obliges checking the install list, and the only thing that settles which list is wrong is a captured gated run (`fixtures/claude-code/permission-recorded`, and the three-lists table in that tree's `README.md`).

- **`doctor`'s `<cli> --version` probes are GATED on presence — several CLIs bootstrap their state dir on ANY invocation.** An unconditional sweep in a pristine HOME created hundreds of entries in exactly the dirs `presence_probe` keys on — the diagnostic manufactured the state it reports (and defeated HOME-isolated e2e). `doctor::may_probe_version` gates the spawn on connected-or-detected, so the observer effect is gone by construction. Accepted: a never-run CLI reports `version unknown` (honest), and a present CLI's probe may still touch its own state. Pinned by `run_never_spawns_a_version_probe_for_a_cli_it_has_no_evidence_of`.
