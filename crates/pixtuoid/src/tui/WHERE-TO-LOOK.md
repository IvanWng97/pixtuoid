# pixtuoid/tui — where to look

Answers for the questions indexed in [`CLAUDE.md`](CLAUDE.md)'s
"Where to look". An entry earns its place only when landing on the
obvious symbol does NOT answer the question.

- "How is the office rendered (pixel pass → terminal)?" → world render = `pixtuoid_scene::pixel_painter::render_to_rgb_buffer`; the terminal flush = `tui::renderer::draw_scene` — the ONE consumer still on the raw call (it needs the full `PixelPassResult` mid-flush); every headless surface rides the shared `floor::render_floor` seam (#423).
- "How does the version popup render?" → `version_popup.rs` windows the notes through the shared `panel::window_range` but with its own `⋮ N more — see the link` marker, because this modal binds NO scroll key (pinned from both sides). The SHIPPED notes are a separate gate (`the_shipped_release_notes_fit_the_classic_terminal_unwindowed` + its harness twin) because fixture-authoring tests stay green while the real arm truncates; both SKIP while `just bump`'s uncurated draft is in the tree. No committed PNG baseline on purpose — a threshold-0 diff would red on every intended notes edit.
- "How does the agent dashboard work?" → PURE model `tui::dashboard` + painter `widgets::dashboard`, called only from the shared `paint_overlays` dispatcher. The `[xx]` badge comes from `mod.rs::source_badge_span` (the ONE builder — dashboard, Sources panel, tooltip) and is deliberately not `REVERSED` on selection (a low-luminance hue inverted vanishes). Modal precedence: onboarding > help > version > connection > dashboard > theme-picker > normal.
- "How does the footer instrument work?" → the tier/policy MODEL is `pixtuoid_scene::footer::build_footer` (shared with the floating painter); `widgets/footer.rs` is a thin adapter. The decode-drift half of `source_warning` comes from `ui_state.rs::DriftScan`, an incremental throttled log scan — the ONE deliberate exception to "no scan-the-history" (a passive diagnostic hint, never lifecycle state).
- "How does the Sources panel work?" → `s` toggles it — the SOLE way to bind/unbind. `build_rows` joins the registry to install targets on `Target.core_source`, NOT `Target.name` (joining on name made the flagship row a no-op; `build_rows_makes_every_source_with_a_target_actionable`). CONNECTION state is cached (rebuilt on open/toggle), LIVE state is per-frame; a Daemon counts INSTANCES through the shared `board::gateway_rollup` — the same rollup the footer chip reads. Failures word through `connection::format_failure`, the ONE producer of the panel's failure sentences.
- "How does first-run onboarding work?" → `setup::is_first_run` (config absent OR `[sources]` empty — a DEGRADED config load is NOT a first run, or apply would fight the never-rewrite rule). Apply routes through `sources::apply_choices`, SCOPED to the detected roster; a Failed row opens the Sources panel ON that row. Skip (Esc) FREEZES each detected source's current state — `[sources]` becomes non-empty so onboarding never re-triggers, and the freeze reflects into the live gate. Headless twin: `pixtuoid setup [--yes]`.
