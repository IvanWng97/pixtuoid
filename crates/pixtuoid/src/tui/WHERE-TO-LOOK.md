# pixtuoid/tui — where to look

Answers for the questions indexed in [`CLAUDE.md`](CLAUDE.md)'s
"Where to look". Each entry is self-contained — grep for your question
and read that one, or read the file end to end when mapping the crate.



- "How is the office rendered (pixel pass → terminal)?" → the world render is `pixtuoid_scene::pixel_painter::render_to_rgb_buffer` (see [`../../../pixtuoid-scene/CLAUDE.md`](../../../pixtuoid-scene/CLAUDE.md) for the pixel-pass split). The terminal-flush pass (`half-block + widgets + status footer`) is **`tui::renderer::draw_scene`**. `draw_scene` is the ONE consumer still on raw `render_to_rgb_buffer` (it needs the full `PixelPassResult` + immutable coffee borrows mid-flush); every headless surface goes through the shared `pixtuoid_scene::floor::render_floor` seam (#423) — the floor-slide calls it directly (projected scenes, caller-side eviction), while `floating::offscreen::OfficeRenderer` and the web hero each own a `pixtuoid_scene::floor::FloorSession` (the scene-owned session whose `render()` also runs the dual eviction); `TuiRenderer` composes the same session halves as `Vec<PerFloor>` + one `PerOffice`. `examples/snapshot/` saves the ratatui `TestBackend` via `save_backend_as_png` (a ▀-compressed PNG with footer).
- "How does the neon wall board work?" → the pixel-buffer half (dark panel + pulsing cyan border) is `pixtuoid_scene::pixel_painter::background::lighting.rs::paint_neon_panel`; the TEXT is a backend-agnostic MODEL, `pixtuoid_scene::board::build_board(counts, uptime, floor, gateway) -> BoardModel` (see the scene guide), which `widgets/wall_board.rs::paint_wall_display` renders as 3 rows of ratatui text by mapping each segment's `BoardTone` → color via `board_tone_color`: **L1** `model.brand` + the `★ Star` CTA (`model.star`, right-flushed; its precise click target is `wall_board::star_hit_rect`, opening `REPO_URL`); **L2** the plain-English **mood pulse** (`model.mood` — one `{glyph}{count} {word}` per non-zero present state, the ▲ "needs-you" beacon LEADING, NUMERIC + abbreviated to fit, from the SAME `scene_stats` the footer reads); **L3** office context (`model.context`: uptime `Dim` + floor breadcrumb + the `⬢gw` gateway chip). The floating window + wasm site paint the SAME `build_board` model their own way (AA / DOM), so all three surfaces can't drift. The board's cell-origin + WIDTH pin to the painted panel's dark INTERIOR — `wall_board::BOARD_W = pixtuoid_scene::pixel_painter::NEON_PANEL_INNER_W` (the outer `NEON_PANEL_W` minus its `NEON_PANEL_BORDER` on each side) and `wall_board::board_cell_origin` starts text at `NEON_PANEL_INNER_X` — so the lit text sits INSIDE the glowing frame (laying it to the full outer width overran it — the board-overflow fix; `paint_neon_panel` reads the SAME border const, so the dark cells it leaves == the cells text may fill). `board_cell_origin` is the ONE origin `paint_wall_display` AND `star_hit_rect` share. **The scrolling ticker was removed** (0.12.0) — `TickerQueue` + the `neon_ticker` theme color are gone; `marquee_window`/`MARQUEE_*` survive (dashboard/connection selected-row scroll).
- "How does the theme PICKER UI work?" → the theme MODEL (the `Theme` struct, `ALL_THEMES`, `SourceColors`/`ApplianceColors`) lives in `pixtuoid_scene::theme` (see [`../../../pixtuoid-scene/CLAUDE.md`](../../../pixtuoid-scene/CLAUDE.md)). The UI is here: press `[t]` for a live preview picker (j/k or ↑↓ to navigate); each row shows a 2-cell swatch (`theme_picker.rs::theme_swatch` → `neon_brand` + `carpet_base`) drawn from that row's own palette. The picker is dispatched in `tui/mod.rs`; `set_theme()` (on `TuiRenderer`) flushes the `FrameCache` so character recolors update immediately. Theme is saved on `[t]` picker Enter confirm in `tui/mod.rs`.
- "How are popups framed?" → **every popup is borderless** (no outline) and shares ONE backing: `widgets/mod.rs::paint_card_backing(f, area, theme)` = a flat single-color drop **shadow** (a hand-rolled fg+bg dim — NOT ratatui's `Block::shadow`, which smears over half-blocks) + `Clear` + a solid `tooltip_bg` fill. **The shadow is a deliberately FLAT offset silhouette, not a soft penumbra** (`cast_drop_shadow`): the card's own rect is darkened by ONE uniform `SHADOW_FACTOR` (0.42) and offset `SHADOW_OFFSET` (1) cell down-right; the card paints over its own cells afterward, leaving an L-band (right column offset down, bottom row offset right, meeting at the corner) — all ONE color. The **bottom-most row is rendered TOP-HALF only** (`dim_cell`'s `top_half_only`: dims `fg`, leaves `bg` lit) so the bottom band reads as a 1px contact line instead of a full 2px cell, while the vertical right strip stays full cells. This is a pinned user preference (matches a supplied reference — flat single color, offset, darker, thin bottom); do NOT "restore" a gradient/falloff or per-band factor, and do NOT make the bottom a full 2px cell — the offset silhouette with the 1px top-half bottom is the intended look (`panel::borderless_panel_casts_a_flat_offset_shadow` pins it). The one thing the band may NOT reach is the footer row — `cast_drop_shadow` clips to `renderer::scene_rect(f.area())` for both card kinds (`panel::a_card_at_the_scene_floor_casts_no_shadow_onto_the_footer_row`); see the every-frame sharp edge for why the clip lives here rather than in `RESERVED_FOOTER_ROWS`. Both card kinds delegate to it, so the look (incl. the shadow) has a single definition and can't drift: `tui/widgets/panel.rs::borderless_panel` calls it, then insets by a uniform `PANEL_PAD_X`/`PANEL_PAD_Y` (the breathing room that replaces the border — now PRIVATE to `panel.rs`, the ONE inset site), draws an optional bold brand-colored title row, and returns the inner content `Rect` (== the shared `panel::inner_rect`, so `PanelGeometry::inner()` and the painter agree by construction). The 6 popups no longer inset by hand — Help / theme-picker / dashboard / connection / welcome route through `panel::paint_panel` (auto-height + `Overflow` list-windowing + cue) and the version popup drives `PanelGeometry` directly (`centered_in` is DELETED); the hover/info tooltips (`tooltip.rs::framed_tooltip`, a `Padding::uniform(1)` text-only Block — the bg/clear/shadow now come from the backing) call it too. Chitchat speech bubbles are deliberately NOT this primitive (a bare 1-row `Paragraph`, no `Clear`/block) so they get no shadow. The title moved from the old border into the body. **The version popup's URL click-rect (`version_popup_url_rect`) is `PanelGeometry::cell_rect` off the SAME `compute` the painter fills** — one geometry authority, so a click can't land where the link isn't painted (phantom-browser-launch, killed structurally; see the sharp edge above).
- "How does the version popup render?" → `version_popup.rs::paint_version_popup` drives `panel::PanelGeometry::compute` (scale from `popup_scale` — entrance EaseOutCubic/200ms, dismissal EaseInQuad/120ms, `pixtuoid_scene::anim`), paints via `borderless_panel(geom.outer())`, and word-WRAPS the release notes to the real inner width (`panel_inner_width`, the height-independent two-phase seam) so a long note never clips. It then WINDOWS the wrapped notes to the inner HEIGHT through the same `panel::window_range` the list panels use: `compute` clamps the envelope to `bounds`, so on a short terminal the notes asked for more rows than exist and ratatui dropped the TRAILING lines — the blank and the `↗ Release notes` CTA. The notes are the windowable band; the link is chrome (`CHROME_ROWS` = leading blank + trailing blank + link). It does **NOT** take their `⋮ N more ▾` cue: that `▾` is what the dashboard/Sources panels page with `j`/`k`, and this modal binds no scroll key at all (`dispatch_key`'s version tier maps Enter to dismiss and swallows the rest), so the chevron promised rows no key could reach. Its own `notes_marker` reads `⋮ N more — see the link`, pointing at the CTA `CHROME_ROWS` keeps two rows below, and truncates to the inner width because the band is wrapped and this row is not. Pinned from both sides — `the_notes_marker_offers_no_scroll_and_fits_its_row` (rendered at 80×24 and 32×31) and `the_version_popup_binds_no_scroll_key`, so ADDING a scroll key here reds the dispatch test and re-opens the wording choice. **The SHIPPED notes are a separate gate, because every test above authors its own fixture and therefore stays green while the real arm is being truncated** (two of them assert the marker IS present — green exactly in the failure state): `the_shipped_release_notes_fit_the_classic_terminal_unwindowed` crosses the real `release_notes(CARGO_PKG_VERSION)` with the real geometry at 80×24, and `harness::overlays::the_shipped_release_notes_render_whole_on_a_classic_terminal` is its render-level twin on the `draw_footer_only_frame` path an 80×24 terminal actually takes. **80×24 is pinned alone on purpose** — the panel never grows past `VERSION_POPUP_W`, so a wider terminal cannot fail, and a shorter or narrower one legitimately windows (that is the marker's job); the arithmetic lives in `the_shipped_release_notes_fit_the_classic_terminal_unwindowed`. Both gates SKIP while `just bump`'s uncurated draft is in the tree (`version::release_notes_are_uncurated`, keyed on the SAME `TODO: curate` marker `just notes-curated` greps) — `bump` runs preflight BEFORE the human curates and its failure trap would discard the draft. There is deliberately **no committed PNG baseline**: `gen-check` pixel-diffs at threshold 0, so a popup still would red on every notes edit — good and bad alike — and be cleared by re-baselining, i.e. an alarm that fires on the intended action (`--flame` is the existing precedent for a `snapshot` flag kept out of `media.json`). The on-demand visual check is `cargo run --example snapshot -- --popup --cols 80 --rows 24 /tmp/popup.png`. The TITLE is likewise sized to the inner width by `version_title`, which drops `What's new in` before it drops `Enter to close` (the title is the only place the modal says how to close itself, and it swallows every other key) and elides with `…` only if even the short form overruns. The clickable link is a COMPACT `↗ Release notes` label (the raw ~46-char URL clipped below ~66 cols and every entrance frame); its screen rect is `version_popup_url_rect = version_geometry(..).cell_rect(link_row, 2, LINK_LABEL)` off the SAME `compute` the painter fills, so a click can't drift from the painted link (phantom-browser-launch class, now a pure test). Click opens `VERSION_POPUP_URL`. (The old `version_popup_envelope` / `URL_PREFIX` / `pulse_border_color` are gone.)
- "How does the `?` help overlay work?" → `tui/widgets/help.rs::paint_help_overlay` paints a centered borderless panel (`borderless_panel`, title "? Keyboard") listing every shortcut (incl. `s` sources). Open state is owned by `UiState.help_open` (toggled by `?`; Enter/Esc/`?` dismiss — the close guard runs BEFORE the version-popup/theme-picker key handlers in `tui/mod.rs`) and mirrored each frame to the renderer's `TuiRenderer::help_open` copy via `set_help_open`. Threaded through `DrawCtx.help_open`, painted last in `draw_scene`.
- "How does the agent dashboard work?" → `Tab` toggles a modal popup: the PURE model `tui::dashboard` + the painter `widgets::dashboard::paint_dashboard`. The model turns `SceneState` into a foldable parent→subagent **tree** (`build_dashboard_rows`: roots by `desk_index`, subagents nested, orphans-as-roots, recursive so deeper nesting is never silently dropped); `DashboardFolds` auto-collapses any root over `AUTO_COLLAPSE_THRESHOLD` (5) so a ~20-subagent CC workflow doesn't flood the board (manual `←/→` fold overrides and STICKS via `user_toggled`; `z` fold-all). Selection is tracked by `AgentId` (`move_selection`/`reanchor_selection` — stable across the 30fps rebuild, re-anchors when the selected agent exits); `Enter` resolves the selected row's floor (`resolve_floor`) and calls `navigate_floor`. State lives in `UiState.dashboard` (persists across open/close for the session); each frame, while open, it builds rows → reanchors → `clamp_scroll` (shared `DASHBOARD_VIEWPORT_ROWS`) → `set_dashboard_frame` to the renderer, which paints the centered/cleared **borderless** popup (via `borderless_panel`) via `DrawCtx.dashboard` (a `&DashboardFrame` bundling `open`/`rows`/`selected`/`scroll`; the row-slice borrow is disjoint from the `floors` (per-floor session halves) borrows; the transition path clones for its brief frames). `paint_dashboard` has ONE call site — the shared `paint_overlays` dispatcher (`renderer.rs`), which takes the whole overlay state as one `OverlayFrame` and which `draw_scene`, `render_transition` AND `draw_footer_only_frame` all route through (centralized so the paths can't drift — see the every-frame sharp edge). Dispatch precedence: onboarding > help > version > connection > **dashboard** > theme-picker > normal (mutually exclusive with the picker; `Tab` only opens from the normal scene, and the modal passes the quit chord through). Model unit tests live in `dashboard/tests.rs`; painter/render coverage in `tui_renderer/harness` (`dashboard_*`). **Per-row presentation** (`dashboard_line`): a leading per-CLI `[xx]` badge built by the SHARED `mod.rs::source_badge_span` (the ONE badge builder, also used by the Sources panel + the tooltip dossier; colors from `pixtuoid_scene::theme::Theme::source`/`SourceColors` via `descriptor_for(row.source).label_prefix`, unknown source → `[??]`/`label_idle` fallback); the agent **name is tinted by `RowState`** (active/waiting/idle); and the badge span is intentionally **NOT** `REVERSED` on the selected row (a low-luminance hue inverted vanishes against the highlight bg — only the name/floor/state spans reverse). A `⋮ N more ▾` cue marks below-window overflow, reserving its own line so it never displaces the selected row (and folding back to full height when the selection scrolls to the very end — no blank line). **The SELECTED row's overflowing name + activity cells auto-scroll** (ping-pong): `marquee_or_truncate` swaps the static `…`-`truncate` for `marquee_window` (a stateless `now`-windowed slice — `widgets/mod.rs`, consts `MARQUEE_MS_PER_CHAR`/`MARQUEE_END_PAUSE_MS`); non-selected rows stay `…`-truncated, the scrolling window emits no `…`, and `[p]ause` freezes `now` (and thus the scroll). The painter takes `now` (threaded through the shared `paint_overlays` dispatcher, so both draw paths agree). Badge-color correctness is guarded by `source_badges_legible_for_every_theme` (`pixtuoid_scene::theme::mod.rs`) + `every_registry_source_has_a_non_fallback_badge_color` (`widgets/dashboard.rs`). For headless capture, the `snapshot --dashboard` flag renders a fixed representative scene (a `cc` parent + 2 subagents + a `cx` root + an `rx` root, `dashboard_scene`) with the popup open — driven by the `dashboard` job in `scripts/media.json` → `docs/images/dashboard.png`.
- "How does the footer instrument work?" → the tier/policy logic is a backend-agnostic MODEL, `pixtuoid_scene::footer::build_footer(&FooterInputs, budget) -> FooterModel` (see the scene guide) — the SAME model the floating painter renders, so the two surfaces can't drift. `widgets/footer.rs` is a THIN ADAPTER: it marshals `FooterStats { counts, per_floor, gateway, audio_audible, volume_flash }` (assembled once per frame at the 3 `paint_footer` sites — `draw_scene`, `draw_footer_only_frame`, `render_transition`) into `FooterInputs` (adding the TUI keybind tails ` [?]help…[q]uit ` / ` [q]uit ` and the pre-merged `source_warning`), then `build_status_spans` tints each `FooterSegment` by its `FooterTone` via the shared `footer_tone_rgb` → ratatui `Color`; `build_status_summary` (`#[cfg(test)]`) delegates to `FooterModel::text()`, the byte-identical text oracle for the insta snapshots. `build_footer` owns the whole ladder: per-state rungs use the shared `StateKind`(=`scene::footer::RungKind`) vocabulary — `●A ◐W ○I ◌x` glyph+count+letter, **exiting a first-class rung** — and the tool tally tints from the TYPED `FooterTone::Tool(kind)` (`pixtuoid_scene::pixel_painter::tool_glow_for_kind`, never a name re-parse); the `▲F{n}` cross-floor cue (from `per_floor_counts`) + `⬢gw {state}` chip (from `gateway_rollup(scene.daemons())`) ride the right-flushed suffix (both ALWAYS present — not hung off `Option<FloorInfo>`); FULL `●3 A · Edit×2 · ⬢gw ok` → MEDIUM `●3A ◐2W ○7I` → MIN `▲N · count` (waiting alarm LEADING) → keys-only, right-flushed to `budget`. **Both surfaces read `scene_stats`** (the anti-drift spine, so footer/board can't disagree mid-walkout). Width is `chars().count()` INSIDE scene (no `unicode-width` there) — byte-identical to this binary's `display_width` because the whole footer glyph vocabulary (·×↑↓●◐○◌⬢▲♩⚠) is single-column, pinned binary-side by `footer_vocabulary_is_single_column_…`. **A source-death warning (#157) preempts the tiers** (inside `build_footer`): when `source_warning` is `Some` (from the runtime health channel via `TuiRenderer::set_source_warning` → the adapter), the warning replaces the stats portion entirely (they'd be stale — the office is partially frozen), truncates-with-… instead of tiering away (it must survive every width, with the `▲N need you` alarm PINNED through truncation), keeps the `[q]uit` suffix, and uses `FooterTone::Warning` = the `label_waiting` attention color (no new theme key). Painted on both the normal and floor-transition paths. **The `source_warning` string is a TWO-TIER merge** (`doctor::footer_warning(source_death, drifted)` in `run_tui`): source-death (highest — a frozen office) short-circuits, else a passive **decode-drift nudge** (`⚠ decode drift: cc· cx· — run pixtuoid doctor`) when any registered source has accumulated `pixtuoid::drift` breadcrumbs. The drift list comes from `doctor::drifted_sources`, which `run_tui` throttle-scans from the warn-floor log (`RunConfig.log_path`, resolved by `main`) at most every ~15s AND incrementally (`tui/ui_state.rs::DriftScan` (scanned by `UiState::build_frames`): a persistent byte offset — each pass reads only the appended COMPLETE lines and merges prefixes, since breadcrumbs are monotone in-session; rotation is startup-only, so an unbounded in-session log must never be re-read whole inline in the ~30fps loop) — the ONE deliberate exception to "no scan-the-history" (it derives a passive diagnostic hint from the log artifact, NOT lifecycle state; a counting `tracing::Layer` was rejected to avoid stateful blast radius on the single global file subscriber). Drift is breadcrumb-driven ONLY — never the `verified_version` skew, which stays advisory in `doctor`. `None` log path (headless) = no drift surfacing. Breadcrumbs from a prior rotated session (in the `.old` log) are not reflected — both the footer and `doctor` read only the primary log.
- "How does the Sources panel work?" → `s` toggles the **Sources** panel (renamed from `c`/"Connection" once it grew past bind/unbind into a per-source board — connection + live + health; the module + types keep the historical `connection`/`Connection*`/`tui::connection` names, only the UI title + keybind changed): the PURE model `tui::connection` + the painter `widgets::connection::paint_connection_panel`. It is the SOLE way to bind/unbind a source — there is **no `install-hooks`/`uninstall-hooks` CLI** (deleted; `pixtuoid` is the only command). ONE navigable list, one row per agent CLI = the **union** of install targets + registry sources keyed on the source id (`build_rows(&connected_set, log)` joins `source::registry::REGISTRY` to install targets via **`install::target::by_source`** — on `Target.core_source`, NOT `Target.name`, which differs for Claude: target `"claude"` vs source `"claude-code"`; joining on `name` made the flagship row a no-op row, the review CRITICAL pinned by `build_rows_makes_every_source_with_a_target_actionable` + `every_target_names_a_registered_source`; Antigravity has no target → connect/disconnect is a flag-only flip). Each row shows a colored `[xx]` badge (same `pixtuoid_scene::theme::Theme::source` mapping as the dashboard, never `REVERSED`), a **Connection** facet (`ConnState`: `connected`/`disconnected`/`no CLI`) and a **Live** facet (`N agents · age` / `idle` for an Agent source, `N gateways · <state>` / `no gateway seen` for a Daemon, or `⚠ transport died`), plus a socket line and a **state-aware detail line** (armed-confirm prompt > last action result > **health verdict** > per-state: Connected → `installed at: <path>`, Disconnected → `press t to connect` (no path — meaningless until bound), NoCli → `<name> not detected on this machine`). **The health verdict** (the #309 health-consolidation: `⚠ install broken: …` > `⚠ N decode drift — run pixtuoid doctor`) is `doctor::diagnose(src, log, None).summary()`, cached on `ConnectionRow.health` and computed in `build_rows` for CONNECTED rows ONLY (`connected.then(diagnose…)` — a disconnected row's stale soundness/drift isn't actionable, and `diagnose` itself gates the install check on `has_hooks`, so a just-disconnected source is never falsely "broken"); it PREEMPTS the benign per-state line. `doctor` is the health PROVIDER, `ConnState` the connection lifecycle it ANNOTATES (sub-state, not overlap). Version skew stays `doctor`-only (the probe is too costly for the panel-open). **Two facets, two lifecycles**: the CONNECTION facet is driven by the live connected-set (the persisted `[sources]` intent) + an FS presence read (`is_present` → `NoCli`), so `UiState.connection.rows` is cached — rebuilt on open + after each toggle (`build_rows(&connected.snapshot(), log)`), NEVER per frame; the LIVE facet (`live_view`) is recomputed per frame from the scene snapshot, and is TYPED by source class (`LiveFacet`): an `Agent` source groups `AgentSlot.source` + max `last_event_at`, a **`Daemon` counts its INSTANCES in `SceneState::daemons` and rolls them up worst-of through the shared `board::gateway_rollup`** — the same rollup + `gateway_label`/`gateway_tone` the footer's `⬢gw` chip and the wall board read, so the panel can't describe a gateway differently from the chip below it. Counting slots for BOTH made every running OpenClaw gateway render `◌ idle`, byte-identical to "never started" (a daemon creates no slot at all), while the same frame's footer said `⬢gw busy`. The row's `dead` flag comes from the captured `&[SourceDeath]` (the same health snapshot the footer reads — no retained renderer map), which is why neither a hook-only source nor the daemon ever sets it: they ride the `HookRouter`'s shared socket, whose own death is attributed in the FOOTER under the infrastructure name `hook-router` rather than on any row. **One toggle, not separate i/u**: `t` on a Disconnected row CONNECTS immediately (additive, reversible — `tui::mod::connect_source`: persist the flag via `config::save_source_connected`, `connected.set(src, true)`, then `install::install_target` for target-bearing rows); `t` on a Connected row arms an inline `y/n` confirm → `tui::mod::disconnect_source` (persist false, `connected.set(src, false)`, `install::uninstall_target`), both via the load-bearing `ConfigLock` round; results render through `connection::format_{connect,disconnect}_result`, and FAILURES through `connection::format_failure(FailedOp, name, reason)` — the ONE producer of the panel's three failure sentences (`connect failed` / `disconnect failed` / the fold's `sources::HOOK_REMOVAL_FAILED_PHRASE`), shared with the onboarding surfacing that lands on this same panel. **The panel's blocking I/O runs INLINE — an accepted brief stall on a one-shot user action.** `connect_source`/`disconnect_source` take an advisory `flock` + `fsync`, and `build_rows` does per-source FS probes + `diagnose` config reads. This was wrapped in `tokio::task::block_in_place` (census #266 escape #1, a #283 bot MEDIUM) until #603 proved the wrap INERT and removed all five sites: `run_tui` is the `block_on` ROOT future (`driver.rs` `new_multi_thread` + inline `rt.block_on`), NOT a tokio worker, so `block_in_place` has no worker core to migrate — it runs the closure inline with zero scheduling effect (it does NOT panic; that's `current_thread`-only). `reducer_task`/sources run on their own spawned worker threads and are never starved by the loop blocking, so the stall freezes only render+input for its (ms-scale; the `flock` is `try_lock` + auto-releasing, so no unbounded hang) duration. The sync `connect_source`/`disconnect_source` fns stay runtime-free so their unit tests run outside a runtime. See the **block_in_place sharp edge** below for why `spawn_blocking` was rejected. The live gate + graceful eviction live in `runtime/driver.rs::reducer_task` (see the binary guide): `connected.set` is the panel's mutation seam, read by the per-event gate + the per-tick reconciler — both in the covered, mutation-tested `runtime::gate` core (`apply_gated_event`/`reconcile_sweep_tick`, driven by `reducer_task`), the latter evicting every slot whose source is the COMPLEMENT of the connected-set (so it also sweeps a blank-source gate-slipper), so a disconnect walks characters out live (no restart). Dispatch precedence: onboarding > help > version > **connection** > dashboard > theme-picker > normal; the open tier splits armed (`y`/`n`/`Esc` only) vs unarmed (`j`/`k`/`t`/`s`/`Esc`); the quit chord always passes through. `s` opens/closes it; bare `c` is now UNBOUND (the panel moved off `c`); only `Ctrl+C` is the quit chord. The socket path + the `ConnectedSources` handle are threaded from `runtime/driver.rs` into `run_tui`. Painted in BOTH draw paths via `DrawCtx.connection` (a `&ConnectionFrame` bundling `open`/`rows`/`live`/`selected`/`confirm`/`result`/`socket_line`). **The SELECTED row's name + the (selection-driven) detail line auto-scroll** when they overflow — `marquee_or_truncate`/`marquee_window` (shared with the dashboard, `widgets/mod.rs`) ping-pong the focused text; the detail line is always the selected row's, so it scrolls whenever its `installed at: <path>` overruns the panel. Non-selected rows stay `…`-truncated. The painter takes `now` (same threading as the dashboard). Headless capture: `snapshot --connection` renders a fixed representative fixture; model tests in `connection/tests.rs`, painter tests in `widgets/connection.rs`, render + dispatch tests in `harness`/`mod.rs`. Badge legibility reuses `source_badges_legible_for_every_theme` + the connection twin of `every_registry_source_has_a_non_fallback_badge_color`.
- "How does first-run onboarding work?" → on the FIRST launch ever (`setup::is_first_run` = config absent OR `[sources]` empty — UNLESS the config load DEGRADED (exists-but-malformed/unreadable ⇒ not a first run: onboarding's apply would be refused row-by-row by the malformed-config-never-wiped rule); computed in `main::build_run_config` and threaded `RunConfig.first_run → TuiSession → run_tui`), the TUI plays a one-time "move-in" overlay — the PURE model `tui::welcome::WelcomeUi` (roster of `sources::detect()`'d CLIs, all pre-checked) + the painter `widgets::welcome::paint_welcome` (borderless, a typewriter subtitle + a STAGED roster reveal, all driven by `OnboardingFrame.elapsed_ms` since open — the model holds no clock).
