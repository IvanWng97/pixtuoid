# pixtuoid-core — known sharp edges

Indexed one line each in [`CLAUDE.md`](CLAUDE.md). These look like bugs and are deliberate design — read the entry before "fixing" one. An entry states the edge, the WHY, and where the authority lives (the pinning test, the in-code comment, or the issue); the full adjudication history is in the cited issue/PR, not here.

- **Only a wire surface we actually READ may raise a drift alarm — don't add a `KNOWN_*` allowlist of names we ignore.** `drift::unknown_event` has no dedup, so such a list must mirror an upstream vocabulary forever or a harmless upstream ADDITION alarms every user (#935). Detect by SHAPE instead — the payload a renamed type still carries. Which sources ALSO need an upstream watch, and why a breadcrumb cannot cover some of them, is decided in `source/drift.rs`'s header — not here, because that answer changes with the decoders. The shape half is pinned by `an_unnamed_type_is_a_turn_only_when_it_carries_the_payload` (CC) and `renamed_planner_step_with_tool_calls_breadcrumbs_and_ends_only` (antigravity); the silence half by `no_sidecar_line_breadcrumbs_whether_or_not_we_have_seen_its_type` and the `*however_new*` tests.

- **There is NO core `render` module and no core render trait.** `blit_frame` is the only pre-scene-split render helper that stays. New render targets are thin painters over `pixtuoid_scene::floor::render_floor` / `pixel_painter::render_to_rgb_buffer` (workspace invariant #1) — do not reintroduce a core render seam.

- **`walkable.rs` is coherence-bound to this crate — it did NOT move with the sim-geometry cluster.** `WalkableMask` is a type alias for `Grid<bool>` whose obstacle ops are an inherent `impl Grid<bool>`, and the orphan rule pins an inherent impl to the crate owning the type. A wrapper struct and an extension trait were both adjudicated against — see the comment on the impl. Producers/consumers live in `pixtuoid-scene`.

- **A daemon's runtime identity is the SOURCE's own wire fact, and for OpenClaw that is the resolved gateway PORT — not the profile, not the pid.** The profile is install-scope, never on the hook wire, and profile↔gateway is 1:N (verified live); the pid churns the mascot on every restart; the session id is many-per-gateway. The port is distinct per live gateway (upstream requires it) and stable across a restart of the same one. `DaemonInstanceId` (stable) vs `DaemonPresence::current_pid` (the incarnation `GatewayUp` rebinds) stay separate so a late exit receipt for a replaced process no-ops; no `PidIdentity` generation guard is needed on this path — the receipt rides the same single-consumer presence channel, so `current_pid == Some(pid)` already covers it.

- **`GatewayDown` CREATES an absent instance; `PidExited` never does — the asymmetry is provenance, not a hole.** `gateway_stop` is a first-hand wire report from a demonstrably-alive process, so materializing it is honest; `PidExited` is synthesized locally, possibly after the gateway was replaced, so creating on it resurrects a phantom (the fbe26049 class) — hence the `current_pid == Some(pid)` guard. Don't harmonize the two arms.

- **`SessionEnded` alone among the presence arms does NOT resurrect a Down gateway — don't harmonize it with its siblings.** The recorded clean shutdown is `gateway_stop` then `session_end` 2 ms later (`fixtures/openclaw/gateway-lifecycle-recorded`), so the sibling arms' "any event ⇒ up" rule would undo the stop the gateway just announced and render it alive until the 5-minute presence TTL — recovery otherwise needs BOTH a `_pid` on the envelope and an exit-watch backend (macOS/Linux only). A session CLOSING is not proof the gateway continues; a real `session_start`/`before_agent_run` still resurrects it. Pinned both ways by `session_end_after_a_gateway_stop_leaves_it_down` and `a_real_event_still_resurrects_a_down_gateway`.

- **A `gatewayPort`-LESS OpenClaw envelope falls back to ONE documented legacy instance instead of being rejected — deliberately.** Upgrading the pixtuoid binary does not re-render the installed plugin, so old plugins stamp no port; a hard reject would silently vanish every existing user's lobster. The fallback reproduces the pre-change behaviour exactly and fires `drift::missing_field` (doctor + footer nudge say reconnect). A PRESENT-but-unusable port still rejects. Don't tighten the absent arm without solving stale-plugin refresh.

- **The two pid→fan-out shells (`HookPidWatch`, the daemon's `PresenceExitWatch`) stay SEPARATE — do NOT hoist a generic `PidFanout<K>`.** The deep primitive is already shared at the right seam (`source/exit_watch.rs::ExitWatch`); each shell is ~12 lines of bookkeeping that differ at every load-bearing point (emitted event, channel — invariant #2's two-channel split — and handle shape), so the generic would be a textbook shallow module. Adjudicated against in the architecture-deepening sweep; the in-code comment in `daemon/native.rs` records the call.

- **`HookPidWatch` arms the exit watch only when one agent reports the SAME pid twice IN A ROW — the one-event lag IS the guard.** A runner that wraps every hook in a per-invocation shell makes `_pid` a corpse-to-be; acting on first sight synthesized a `SessionEnd` after EVERY hook (#896, cursor). A per-invocation wrapper reports a fresh pid each time and can never be corroborated — that kills the class, for wrappers no interposer list has heard of. Corroboration is CONSECUTIVE (a later pid replaces the sighting) so a recycled pid is out of reach. **opencode deliberately arms on sight**: its `_pid` is the plugin's own `process.pid` (`PluginStamp`), and a no-tool-call session reports it exactly once. Pinned by `a_batch_yields_one_bind_target_per_agent` + the `Bindings` suite.

- **The `native` (default) feature gates the ASYNC SOURCE RUNTIME, not the decoders — and the gates are MODULE-level, not item scatter.** `default-features = false` drops tokio/notify and every runtime half (`hook/`, `jsonl/`, `manager`, probes, each source's `native.rs` sub-module behind ONE parent gate + re-export), leaving the wasm32-clean decode/reduce core. Decoder fns and the registry stay always-compiled (registry rows name them as data). The second feature, `harness` (non-default), keeps the offline `Drive` driver out of the shipped lib and the semver surface; core dev-depends on ITSELF by path to turn it on for dev targets (the standard workaround, rust-analyzer#20836) — don't "clean it up" into a normal dependency, that ships the harness. `just hack` catches host-side ungating; wasm32-only breakage surfaces only in `wasm-check`/`just gen-wasm` — host-green ≠ wasm-green.

- **The per-CLI home resolvers MIRROR each CLI's own; the axes deliberately NOT mirrored are listed here** (#880). Where a source tails a transcript, an unmirrored axis is fail-silent (empty office, no error), so each axis was audited against the shipped artifact — don't "fix" these: copilot's `--config-dir` flag (per-invocation, unobservable) and its XDG dirs (legacy-migration-only); hermes profiles (applied by a wrapper exporting `HERMES_HOME`; upstream calls the mismatch a bug, `NousResearch/hermes-agent#18594`); CC's NFC / grok's `dunce` normalization (same directory either way). Whitespace overrides are treated as unset (CC/copilot take them literally; we can't resolve a relative dir). A RELATIVE override is unmirrorable — each CLI resolves it against its own cwd; `platform::warn_if_relative_override` warns and passes through. omp is the deepest mirror (`node_join` home-anchored `PI_CONFIG_DIR`, `OMP_PROFILE` wins-when-present, XDG flattens `agent/` — hence `omp_sessions_dir`), and one omp axis is named-not-mirrored: `.env` files can relocate its sessions dir invisibly; reading them is the fix if it ever bites. No resolver axis is watched upstream any more — those rows scraped omp's and hermes's source trees and went with the rest — so re-run the probe matrix against the shipped artifact when a CLI majors.

- **The hook-wins dedup is asymmetric BY EVENT KIND (#150).** A recorded hook End suppresses both JSONL kinds (covers the tool's lagged pair), but a recorded hook Start never suppresses a JSONL End — when the best-effort PostToolUse hook drops, that JSONL End is the only completion signal, and eating a Task self-End would leak `active_tasks` all session. The kind lives in the map VALUE (an End overwrites its tool's Start entry) — kind-in-the-key or exact-kind matching both regress `late_batched_jsonl_pair_after_delivered_hook_end_is_fully_dropped`.

- **That dedup is also ONE-directional — a JSONL-first tool inflates `tool_call_count` by 1, cosmetically.** Only the hook arm writes `recent_hook_tool_uses`, so when JSONL wins the two-task delivery race both copies apply. The count only feeds the hover tooltip; a symmetric reverse-dedup would cost a hot-path map write for a tooltip metric. Don't "fix" it by also counting in the JSONL arm — that IS the double-count.

- **The `active_tasks` insert in `track_active_tasks` is not slot-gated, and that's HARMLESS — don't add a `contains_key` guard.** A desk-exhaustion orphan entry eats nothing (every reader is slot-guarded) and `tick`'s retain reaps it within ~1s; gated vs ungated is byte-identical empirically (#612). Leave the hot arm alone.

- **The JSONL watcher's DECODED-event send is blockable, unlike the hook path's `CONN_TIMEOUT` — a deliberate asymmetry.** Dropping a decoded transcript delta would desync the per-file cursor's tail-follow (which assumes no gaps), so `walk_jsonl` awaits the bounded reducer channel with no timeout (worst case: delayed detection, self-recovering). The upstream PATH channel IS bounded via try_send-drop (#585) — a dropped path is safe, the next pass re-walks it. Don't add a send-timeout on the decoded side.

- **CC keys on the session UUID, not the transcript path.** Hook `IdKey::SessionId` == watcher `cc_id_from_path` (filename stem) == `detect_parent_id`'s `<parent-uuid>` path component, which makes the subagent→parent link cwd-split-safe (a worktree subagent transcript differs only in the cwd-derived prefix). Antigravity keying and CC's `SubagentStop` arm fold paths through `id::normalize_path_key` (Windows verbatim-prefix strip #197 + casefold). Pinned by `hook_and_watcher_keys_coalesce_for_one_file` (+ windows twins). Route any new CC keying site through `cc_id_from_path`, any Antigravity site through `normalize_path_key`.

- **CC hook `transcript_path` always points to the PARENT'S transcript**, even when a subagent acts — so subagent tool hooks hash to the parent, and the reducer suppresses hook activity for any agent inside a `Task` (`active_tasks`); correct child attribution arrives via the per-subagent JSONL. Since #241 CC's own `SubagentStart`/`SubagentStop` hooks are decoded (registry `hook.custom`): Start registers the child instantly with the parent link; Stop emits the child's `SessionEnd` — the ONLY end signal a Workflow-fleet subagent gets. Keying nuance: the wire `agent_id` is bare hex while the watcher's space is `agent-<id>`; Stop keys on `cc_id_from_path(agent_transcript_path)` (authoritative), wire id as fallback. Fixtures: `tests/sources/claude/`.

- **The subagent-dispatch tool is detected SEMANTICALLY — by `subagent_type` in the input — with the name `Agent` only as fallback.** CC renamed the tool `Task`→`Agent` undocumented (v2.1.63, issue #29677), which silently broke name-only matching (parent showed the child's tools, observed live). An unrecognized dispatch name still works and logs the `unknown_dispatch` drift breadcrumb. Don't revert to name-only matching; the legacy input-less `Task` arm was dropped in 0.12.0 (accepted).

- **Liveness flows UP the subagent tree** (`scope::refresh_lineage`): any activity refreshes `last_event_at` for the actor and every ancestor, so a delegating parent isn't stale-swept while its subagent works — whether the work arrives as a suppressed hook or the child's own JSONL. It is the mirror of `cascade_exit` (which pushes exit down). Don't drop the up-refresh from the suppress block: a single >10-min delegation would make the live parent look stale and evict its working subtree.

- **The JSONL first-sight gate runs on EVERY path a file is first seen — seed, 250ms rescan, 60s poll, notify — not just startup (#85).** `walk_jsonl::should_seed_at_eof`: outside `DEFAULT_INITIAL_WINDOW` (1h) OR carrying an end marker in the last `TAIL_BYTES` ⇒ cursor parks at EOF, no `SessionStart` (else hundreds of stale sessions saturate the desks). Symlinked entries under the root are refused wholesale (`symlink_metadata`). It used to gate only the initial seed; losing the APFS `read_dir` race then let the rescan resurrect a stale session as a phantom — that unification is the #85 fix.

- **"Recent" is the source's own ACTIVITY clock where it has one, not the file mtime.** CC writes session-metadata sidecars into OTHER, dead sessions' transcripts, bumping mtime (capture-verified) — so CC supplies `ActivityRecency` over the same tail the end-marker scan reads. Its three-state verdict is load-bearing: `At(secs)` gates on the newest turn, `Unknown` keeps mtime's verdict, and `SidecarOnly` GATES — parseable-but-turn-less is EVIDENCE the write was metadata, not absence of evidence (an `Option` collapsed exactly this and re-admitted the ghost; widening the tail window can't fix it, sidecar lines are unbounded). An unrecognized line type is sidecar evidence UNLESS it carries the turn payload (`message.role`+`content`) — that payload is what stops a renamed TURN type gating every live session at once, and a renamed payload-LESS activity type (`system`, `attachment`, `file-history-delta`, `queue-operation`) falls into the accepted residual instead. Other sources keep pure mtime until the same write is observed on THEIR wire.

- **A liveness-probe vouch bypasses the gate's RECENCY half, NEVER its terminator half.** A vouch answers "is the owning process alive", not "is this session over" (omp's fd vouch fires for a bun tool merely READING an old transcript); a structural end marker is the source's own first-hand report and outranks any proxy. A vouched ENDED transcript parks at EOF unregistered; `revouch_gated_files` re-checks before resetting a cursor. Probes: CC's `sessions/<pid>.json` registry (pid-alive + the #220 start-time identity check against recycling), Codex/omp open-fd binding (`fd_probe`) — each attached only under that CLI's first-party layout, so fixture replays keep pure-mtime behavior.

- **The exit ladder is instant (ms) > negative vouch (~60–120s) > ProofOfLife TTL + stale sweeps — and a probe FAILURE changes nothing.** `LivenessProbe` returns `Option<ProbeSnapshot>`: `None` = enumeration failed, watcher freezes state (no miss windows age); `Some(empty)` = a healthy "nothing alive". A previously-vouched id missing from two healthy snapshots ≥60s apart (`NEGATIVE_VOUCH_MIN_SPAN`, immune to Codex's drop-and-reopen fd gap) gets a synthesized `SessionEnd` — the exit the CLI never writes; the confirm also un-claims the path so a resume self-heals on its next write. Above it, ONE `exit_watch.rs` thread (kqueue/pidfd; every failure degrades to the rungs below) emits within milliseconds through the SAME `emit_session_exit` path. ProofOfLife meanwhile only refreshes the reducer's reap exemption — it never creates slots, never touches activity state, never delays ends. Pinned by the `tests/watcher/liveness.rs` + `tests/reducer/liveness.rs` suites.

- **An OVERSIZED pending span (>1 MiB) is skipped to EOF, never replayed — but it still registers (#204) and rescues in-flight Task dispatches (#222).** The tail 256 KiB is scanned for UNMATCHED Task dispatches and exactly those re-emit (Task-seeding, not a replay), restoring subagent-leak suppression + b1 completion on mid-attach to a delegating parent. Everything else decoded by the scan is discarded; the terminator still wins. Residuals bounded and pinned by `oversized_attach_dispatch_outside_window_is_missed`.

- **Watch backend: native in prod, polling in tests — don't wire real FSEvents into tests.** A real FSEvents stream costs tens of seconds per test to set up; `force_polling_backend_for_tests` swaps in `PollWatcher` (~25ms, `with_compare_contents` — the change-date diff misses rapid appends). Both impl `notify::Watcher` into the same channel; the seam swaps delivery only, and the gate logic stays covered watcher-free by the `walk_jsonl` unit tests.

- **A hook event from an UNKNOWN session id REGISTERS it — hooks are proof of life; JSONL events for unknown ids stay no-ops.** A hook only comes from a live process, and a permission-parked session appends nothing to its transcript (no JSONL revival path). `decode_hook_payload` attaches `AgentEvent::Identity` ahead of activity events, so registration lands with real source/session_id/cwd (a blank ordinal-labeled slot is the fallback, exempt from the unknown-cwd reap; the next real `SessionStart` back-fills first-wins, label upgrades gated by typed `SlotLabel` provenance). The transport boundary is deliberate: a transcript line can be a historical replay, so JSONL never synthesizes (`jsonl_event_for_unknown_id_stays_a_no_op`), and end-ish events (`SessionEnd`/`Rename`) don't either. Pinned by the proof-of-life + `hook_identity_*` suites in `tests/reducer/lifecycle.rs`.

- **A refused (desk-exhausted) hook registration must NOT record its `tool_use_id`** — the stale record would dedup-eat the JSONL `ActivityStart` that finally registers the session once a desk frees. The record is gated on the slot existing post-synthesis; pinned by `refused_hook_registration_does_not_poison_dedup_for_the_later_jsonl_copy`.

- **A child's end is remembered by tombstone (5s) + child ledger (#244/#246) — and the ledger rides TWO deliberately different clocks.** The 5s `SessionEnd` tombstone gates only unknown-id reorder skew; the reducer-private ledger remembers each child's APPLIED parent link plus `ended_at`, gating late parented re-starts for 90s (`CHILD_END_LEDGER_TTL`, past the 60s poll) while RETAINING the entry 300s (`CHILD_END_RELINK_TTL`) so a parentless revival start ADOPTS the remembered parent (through the #240 cycle filter). Sharing one clock made a multi-turn child idle >90s re-register as an orphan — the exact phantom adoption eliminates. The multi-turn Codex child has NO upstream SessionStart carrier at turn N+1 (verified against hook_runtime.rs), so the **child-end un-claim side-channel** (`jsonl/unclaim.rs`) manufactures one: the hook-router tee (`HookRouter::run` — the one socket every source's hooks ride) pushes every hook `SessionEnd{as_child}`, each watcher drains ids matching its own paths — pending bytes walked first (#228), no SessionEnd emitted, claim RELEASED not removed (a removed claim would let re-vouch replay the whole rollout) — and the next append re-registers + re-links via ledger adoption. Deliberate residuals (parentless-revival legitimacy, the Stop-before-Start reorder, in-grace swallows) are enumerated by the pinning suites: `tests/reducer/child_ledger.rs`, `tests/watcher/unclaim.rs`.

- **CC has no durable JSONL exit record — and user-controllable content must never drive lifecycle.** Modern CC persists no `/exit` marker, and the old content-based `<command-name>` matcher false-positived on messages QUOTING it, so `cc_session_ended` matches only structural `session_end`/`SessionEnd` markers (which CC doesn't write today; the drift watch flags it if that changes). The `SessionEnd` hook is the one clean-exit signal and it is best-effort; Ctrl-C/kill produce nothing and fall to the exit ladder / stale sweeps.

- **Codex Idle reaps at 5 min (`STALE_SHORT_IDLE_TIMEOUT`); CC keeps 30 — don't add a short CC reaper.** The policy is registry-derived (`SourceCaps::short_idle_reap()` = `!has_exit_signal && resurrects_on_prompt`): safe wherever that capability pair holds (Codex and grok today — `short_idle_reap_fires_for_codex_and_grok_only`) because the false-positive self-heals (the next prompt re-emits `SessionStart`), and a vouched slot is exempt while the fd stays open (#220). CC's clean exits already signal via the hook, so a short CC reaper would only evict legitimately-idle live sessions. Codex's #710 `SessionEnd` hook is teardown-only and best-effort — enrichment, not the lifecycle authority. Pinned by `codex_idle_agent_reaps_faster_than_claude_idle` + `codex_vouched_idle_slot_outlives_short_idle_reap`.

- **Two guards stop a stale-swept parent's cascade from evicting a LIVE subagent** (k8s liveness-vs-readiness): liveness up-propagation (`refresh_lineage`) keeps ancestors of a working child fresh, and `has_waiting_ancestor` exempts a child blocked under a Waiting parent — "not ready", not dead. The cascade fires only once the whole subtree is genuinely silent.

- **The b1 Task-drain cascade is grace-DEFERRED (2.5s, #151), and the chained-dispatch linger is unbounded — don't restore immediacy.** A parallel second dispatch is only visible via its lagged JSONL copy; an immediate cascade at the first drain would evict that LIVE subtree unrecoverably (`exiting_at` has no clearer). Any Task insert inside the grace cancels the pending cascade; a sequential re-dispatch defuses it, so a completed wave waits for the next drain-to-empty (worst case the idle sweep) — the price of never evicting a live subtree. Residuals accepted in #151.

- **A subagent registered AFTER its parent's cascade escapes it — deliberate, because a parent's `exiting_at` is NOT a terminal verdict.** Both obvious fixes were adjudicated against: REFUSING the registration breaks the live-parent-false-exit re-adopt (a wrongly-ended CC parent re-registers under the same `AgentId` and silently re-adopts its children), and INHERITING `exiting_at` is the b1 hazard verbatim (no clearer; `resurrect_in_place` exists because a root's exit is revocable). A durable fix must key on something that outlives the slot (the child ledger); tracked, not patched at the register arm.

- **Resurrect-in-place starts from clean correlation state.** A `SessionStart` on an EXITING root cancels the walkout AND evicts the dead life's `active_tasks`/`gated_before_waiting`/`pending_b1_cascades` (a leftover tuid can never drain, so it would suppress every hook of the new life); the proof-of-life vouch deliberately survives — the resurrecting process is alive by definition.

- **Codex subagents are wired via the `SubagentStart`/`SubagentStop` HOOKS, not JSONL paths.** A Codex child's rollout is FLAT under `sessions/`, so the hooks are the only carrier of the parent link (child keyed on `agent_id` == its rollout UUID, coalescing with the watcher's slot). The `SessionStart` arm ENRICHES an existing orphan's `parent_id` (never re-parents, and refuses any link closing a cycle — `scope::would_create_cycle`, checked at this one seam, #238); multi-turn children re-link via the un-claim + ledger flow above. Wire format pinned in `tests/sources/codex/mod.rs`.

- **Subagent display names come from `attributionAgent` in JSONL** (plugin prefix stripped → `AgentEvent::Rename`); parents get their cwd basename, and `cc_derive_label` falls back to the CC project dir on an empty-cwd seed so a Rename never degrades `cc·dotfiles` to bare `cc`.

- **`AgentSlot.state_started_at` is process-local `SystemTime`, and `SceneState`'s serde derive is NOT a wire contract.** The pose system computes elapsed time against it — don't wall-clock-anchor it. The `Serialize`/`Deserialize` tree (#279, `*_serde` adapters for the `Arc` fields) exists for debug dumps + the insta golden; adding a slot field is non-breaking.

- **`ActivityState::Active` ≠ "tool is currently executing".** PreToolUse→PostToolUse fire around every call, so `ActivityEnd` only ARMS pending-idle; `tick` realizes Idle after `ACTIVE_GRACE_WINDOW` (1.5s), and any Start inside cancels it. Visible Idle lags real Idle by up to ~2.5s — don't depend on instant flips.

- **grok leader-mode sessions are DELIBERATELY UNVOUCHED (#826) — the #638 socket vouch was deleted, not repaired.** `--leader` runs the agent in a shared process while `active_sessions.json` records only each TUI client's pid, so a client detach reads as exit. The repair was adjudicated against twice: the probe asked `open_vnode_paths` for a unix socket (structurally never reported — pinned by `open_vnode_paths_never_reports_a_unix_socket`), and even a byte-perfect probe couldn't reach the symptom (the client pid still won the `ExitWatch` binding). No correct in-tree fix exists — session→leader ownership lives only in the leader's in-memory maps, and every disk surface answers a different question; the real fix is upstream exposing the fact (#839). Leader sessions ride the pre-#638 path (mtime gate + short-idle reap + prompt resurrect), as they have for the feature's entire shipped life.

- **grok fires OTHER CLIs' hooks with GROK envelopes — the cross-fire guard drops them QUIETLY.** grok scans `~/.claude/settings.json` and `~/.cursor/hooks.json` by default and executes those shim commands, so duplicates arrive tagged `claude-code`/`cursor`; `decode_hook_payload` drops any `hookEventName`-carrying payload whose tag isn't grok, at trace level, before the custom decoders — else CC/cursor would Err per grok tool call.

- **grok's `spawn_subagent` defaults `background=true`, where `post_tool_use` fires at SPAWN — so `ToolDetail::Task` is minted ONLY for explicit `background:false`.** Treating a background spawn as a Task would let the b1 drain-cascade evict the LIVE child ~2.5s after spawn (End == spawn, not completion). Background children lose only the parent's Delegating pose — they are first-class, child-keyed, with wire-carried ends. `rawInput` carries CLIENT-form keys, so `spawn_is_blocking`'s both-keys read is load-bearing, not defensive.

- **The permission `Waiting` resolves on the gated tool's PostToolUse — and the gate (`gated_before_waiting`) has SEVEN clear sites whose conditionality is load-bearing.** The two eviction sites (`tick` retain, `sweep_exited` remove); the two unconditional turn-boundary clears (`apply_activity_start`, `apply_activity_end`); the Task-drain clear, CONDITIONAL on the drained tuid matching (unconditional would wipe a parallel ordinary tool's gate — `task_drain_keeps_parallel_ordinary_tool_gate`); the suppress-restore clear, only for a Task tuid (`suppressed_child_event_keeps_parents_own_parallel_tool_gate`); and the RE-NOTIFY clear in `apply_waiting`, skipped while the slot is already `Waiting` — CC follows its tool-less `PermissionRequest` with the idle `Notification`, and clearing there loses the tool whose PostToolUse is the only thing that resolves the wait (`a_second_waiting_keeps_the_gate_the_first_one_remembered`). Keep the sites in sync if you touch eviction.
