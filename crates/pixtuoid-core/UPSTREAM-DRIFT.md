# pixtuoid-core — keeping the decode mapping current

Upstream wire contracts change without notice. The four defenses, and every source's watched surface.

Tool names, hook-event names and transcript types are upstream wire contracts that change **without notice** (the `Task`→`Agent` rename shipped undocumented). Four defenses, in order of reliability:

1. **Resilient detection (in code).** Prefer a *semantic* signal over a hardcoded name where one exists — e.g. `make_tool_detail` keys subagent dispatch on the stable `subagent_type` input field, not the tool name. This survives a rename by construction.
2. **Self-monitoring from the real stream (in code).** The decoders already see ground truth — and the breadcrumbs are now STRUCTURED: `source/drift.rs` (always-compiled) owns the four decode-drift breadcrumbs (`unknown_event`/`missing_field`/`unknown_dispatch`/`shape_drift`), each a `tracing::warn!` on the stable target `pixtuoid::drift`, so the warn-floor log and `pixtuoid doctor` surface them. An unrecognized `hook_event_name` VALUE → `unknown_event`, and an ABSENT `hook_event_name`/`session_id` KEY → `missing_field` (the two shared-arm bails are the whole hook plane's chokepoint — an upstream rename of either kills every hook event of every source riding them, and a plain `warn!` lands on a target `doctor::parse_drift_line` cannot see; undeduped is flood-safe on this plane, which carries only payloads we've committed to decoding, and the documented grok cross-fire is dropped quietly before them); a dispatch under an unknown name → `unknown_dispatch`; the `sessions/<pid>.json` registry consumer's once-per-run shape warn (#247 — the canonical instance of this defense for a NON-FETCHABLE surface defense #4 can't reach) → `shape_drift`. These surface drift the moment it appears in a user's own usage — no network, no upstream-layout dependency.
3. **Internal consistency test.** `every_registered_codex_event_decodes` / `every_registered_cc_event_decodes` (in `install/{codex,claude}.rs`) assert that every hook event we *register* has a decoder arm — catching the *registered-but-not-decoded* class (the original SubagentStop bug) at `cargo test` time.
4. **Upstream watch (CI).** `scripts/check_upstream_drift.py` + `.github/workflows/upstream-drift.yml` (weekly) read the names we depend on directly from our source and compare to live upstream; on a name WE READ vanishing upstream it opens a deduped `upstream-drift` issue. It watches the VANISH direction for names we read; the one deliberate exception is `CC_LIFECYCLE_SURFACE_MARKERS`, which fires when a surface we depend on the ABSENCE of (a structural `session_end` record, the sessions registry) APPEARS. **A finding's DISPOSITION is load-bearing and the report keeps three apart**: a *verified change* (we read the surface that OWNS the name and it is gone → fix the decoder), a *review ping* (a surface worth adopting appeared), and *probe health* (`blind` — a 404, a missing anchor, a parser that found nothing: all the script knows is that ITS OWN PROBE missed, so the affected checks are SKIPPED and the fix is to repin, never to edit a decoder). The report's H1 carries the disposition and IS the issue title — the workflow reads it back rather than keeping a second copy of those strings. Every document swept for name-presence declares an **anchor** in the script's `ANCHORS` table — ideally the declaration that owns those names, else one co-located with them (the table marks which grade each row is; a docs *page* can only ever be the weaker one) — and no anchor means no sweep. This is the #793 lesson: absence is only evidence of a rename if the owning declaration is still there. CodeWhale split `crates/tui/src/hooks.rs` into a module directory, the stale pin kept returning 200 as a `mod`/`pub use` facade, and the unanchored sweep reported three WORKING `DEEPSEEK_*` env vars as renamed under "decoder will silently drop events" — 5 of that report's 6 findings were false positives. **Adding a new swept document means adding its anchor** (an undeclared URL is reported as probe health and never swept) and a sample to the selftest's `ANCHOR_SAMPLES`, which tests the gate both ways: a pure upstream refactor yields probe health, an intact anchor still hands the body to the sweep. Those samples are hand-written to match, so they prove the GATE — never that an anchor is CORRECT against the live document; a typo'd anchor surfaces as a permanent weekly probe-health line. **Coverage is both EVENT/TYPE names AND payload FIELD names** — a renamed field is the same silent-failure class (the decoder reads `None`, the sprite quietly breaks), so beyond the event lists below the watch also checks the FIELD names each decoder reads wherever the upstream owner is fetchable. Each is ONE-DIRECTIONAL (only a VANISHED depended field alarms) and the field SETS are hardcoded literals next to the code, maintained by review. **When you add/remove a wire field the decoder reads, update that source's `*_PAYLOAD_FIELDS` set.** Cursor + CC (closed binaries, docs-prose) and Antigravity (no fetchable schema) can't be field-watched — defense #2 is their limit. Sources:
   - **Codex** (open Rust): `codex-rs/protocol/src/protocol.rs` `HookEventName` enum (raw on `main`). `PreCompact`/`PostCompact` are intentionally not registered — not agent activity. **Plus the ROLLOUT decode vocabulary** (#500): the transcript decoder's `("event_msg"|"response_item", …)` arms are registered NOWHERE, and its tail is SILENT on every outer and inner alike. `read_codex_rollout_types` diffs each depended INNER type against the `EventMsg` enum (protocol.rs) + the `ResponseItem` enum (`codex-rs/protocol/src/models.rs`) — one-directional (only a VANISHED depended type alarms). `task_started`/`task_complete` count via their `#[serde(alias="turn_started"/"turn_complete")]`.
   - **CC** (closed binary — no source to grep): the docs markdown `code.claude.com/docs/en/tools-reference.md` (authoritative tool-name list) **and `hooks.md`'s hook-event summary table** — diffed against `install/claude.rs` `EVENTS` (now incl. SubagentStart/SubagentStop, #241), so a registered event vanishing is a verified change. Tool names like `Agent` are NOT schematized upstream, so defense #2 is the real backstop for CC. **The TRANSCRIPT tail also breadcrumbs** (#763): `decode_cc_line` alarms on the two conditions that cost us events — a `DECODED_TYPES` member (`assistant`/`user`) whose `message` object is GONE (`missing_field`), and an UNKNOWN top-level `type` arriving with a turn payload, `message.role` + `message.content` (`unknown_event`). CC is the non-fetchable class, so this is defense-#2-only with **NO CI drift-watch**. The discriminator is measured, not assumed: over a live `~/.claude/projects` corpus of 2,974 transcripts / 471k lines / 18 distinct types, `message.role`+`content` appears on `assistant` and `user` and on NO other type — re-measure before widening it. Guarded on the LOW-cardinality top-level `type` (session-freq) — NEVER the HIGH-cardinality inner `attachment.type` (`hook_success` streams ~per tool-call, would flood).
   - **Reasonix** (open Go): `internal/hook/hook.go` `Event` consts + the payload json tags (`event`/`cwd`/`toolName`/`toolArgs`/`subject`/`message`) on `main-v2`. `PostLLMCall`/`PreCompact`/`SubagentStop` are intentionally not registered.
   - **CodeWhale** (open Rust): `crates/tui/src/hooks/config.rs` `pub enum HookEvent` (snake_case wire names) on `main`, diffed against `install/codewhale.rs` `CODEWHALE_EVENTS`; the `DEEPSEEK_*` env-var check fetches its sibling `hooks/executor.rs` separately. (Both lived in a flat `crates/tui/src/hooks.rs` until upstream split it into a module directory — the old path still 200s as a `mod`/`pub use` shim, so a stale pin reads EMPTY rather than 404ing and reports every depended name as vanished, #793.)
   - **opencode** (open TS): the `EventV2` `type` literals in `packages/schema/src/v1/session.ts` + `packages/schema/src/permission.ts` on `dev` (the `main` branch was retired and the schema moved out of `packages/core/`, #406), diffed against the `match event` block in `source/opencode.rs`. ONE-DIRECTIONAL: only a VANISHED depended type alarms. `OPENCODE_TOLERATED` skips the defensive `permission.asked` alias.
   - **Copilot** (published JSON schema): the per-event `type` consts in the per-platform `@github/copilot-<os>-<arch>` (e.g. `copilot-linux-x64`) `schemas/session-events.schema.json` (served by unpkg, UNPINNED — follows the redirect to latest; the root `@github/copilot` is now a loader stub that 404s the schema, #406), diffed against the `match kind` block in `source/copilot.rs`. ONE-DIRECTIONAL like opencode (Copilot emits ~100 types, we map ~10) — only a VANISHED depended type alarms. The transcript tail breadcrumbs NOTHING. `upstream_copilot_namespaces` survives as this document's ANCHOR gate — an unparseable `SessionEvent` union SKIPS every Copilot check rather than reporting each field renamed.
   - **Cursor** (closed binary): the camelCase `hook_event_name`s on `cursor.com/docs/hooks`, diffed against `CURSOR_EVENTS` in `install/cursor.rs`. ONE-DIRECTIONAL: only a VANISHED depended event alarms (we register 6 of the ~19 the docs list). The common-word `stop` is low-confidence (the docs page contains the word regardless), so the distinctive `sessionStart`/`sessionEnd`/`preToolUse`/`postToolUse` carry that half. Cursor's DECISION hooks stay unregistered on purpose — the shim always exits 0, so answering one would be a lie.
   - **OpenClaw** (open TS): the hook-event types in `src/plugins/hook-types.ts` on `openclaw/openclaw` `main`, diffed against `OPENCLAW_EVENTS` in `install/openclaw.rs`. ONE-DIRECTIONAL: only a VANISHED registered event alarms (we register 6 of upstream's 42).
   - **Hermes** (open Python): `VALID_HOOKS` in `hermes_cli/plugins.py` on `NousResearch/hermes-agent` `main` — the declaration that OWNS the vocabulary — diffed BOTH WAYS (#932) against `HERMES_EVENTS` in `install/hermes.rs` (5 events; `pre_approval_request` was added by #929, whose capture showed hermes DOES announce approvals). We register 5 of upstream's 37; the believability FLOOR (`PARSE_FLOORS["hermes"] = 30`) is what keeps a partial fetch of that page from filing 5 false ⛔. The vanish half read `_DEFAULT_PAYLOADS` in `hooks.py` until #929 — the `hermes hooks test` fixture set, which does not list every hook, so it filed a verified ⛔ against an event we hold a capture of (#793's rule, on our own report). Registering an approval hook is safe only while a SHELL hook's exit code cannot stall one — pixtuoid installs a shell hook, not a Python plugin — so the premise is watched at `_BLOCKING_EVENTS` in `agent/shell_hooks.py`, the frozenset gating `returncode == BLOCK_EXIT_CODE`. It MOVED there from `hooks.py`; #929 briefly read that move as a deletion and swapped in a prose sentence from `plugins.py`, which governs Python PLUGIN return values — the wrong mechanism.
   - **kimi** (closed binary, docs-prose — the Cursor posture): the hook names on kimi's Event Reference page, diffed against `KIMI_EVENTS` in `install/kimi.rs`. ONE-DIRECTIONAL: only a VANISHED registered event alarms (we register 8 of upstream's 20). (`PermissionResult` is the post-decision half of the gate whose ASK half we DO register).
   - **grok** (open Rust, `xai-org/grok-build`): THREE depended surfaces (`read_grok_events` + the transcript checks) — the hook events (`GROK_EVENTS` in `install/grok.rs`, read from `xai-grok-hooks/src/event.rs`), the ACP transcript xAI-extension vocabulary (`extensions/notification.rs` — a versioned protocol NOT fetched here, pinned UPSTREAM by grok-build's own `wire_tags` guard test, not ours), and the `active_sessions.json` liveness-registry struct (whose crate MOVED to `crates/codegen/xai-grok-active-sessions/` — the old pin 404'd). All three are ONE-DIRECTIONAL: only a VANISHED registered/depended name alarms. grok's TRANSCRIPT axis breadcrumbs NOTHING, and the shared ACP decode in `source/acp.rs` ignores every `sessionUpdate` tag but `tool_call`/`tool_call_update`.
   - **omp** (open TS, `can1357/oh-my-pi`): TRANSCRIPT-ONLY — the entry `type` discriminators (`read_omp_entry_types` vs `source/omp.rs`'s `match kind`), diffed one-directional like copilot (omp emits more types than we map — only a VANISHED depended type alarms). The tail breadcrumbs NOTHING.
   - **Antigravity** is deliberately **defense-#2-ONLY** — NO drift-watch row (defense #4). It's a closed Google IDE, and while its on-disk `transcript.jsonl` wire IS partially observable (a Google Cloud Community tutorial + the confirmed on-disk path `~/.gemini/antigravity-cli/brain/<id>/.system_generated/logs/` quote real lines: field set `{step_index, source, type, status, created_at, content, tool_calls}`, step types incl. `USER_INPUT`/`PLANNER_RESPONSE`/`SEARCH_WEB`), that is illustrative SAMPLE wire, not a stable published schema — so it is NOT a reliable `check_upstream_drift.py` source (same NON-FETCHABLE-SCHEMA class as the CC `sessions/<pid>.json` registry, #247; do NOT add a reader — there is nothing stable to fetch). Only `query` (the `search_web` arg) is capture-confirmed; the rest of `decode_ag_line`'s tool-arg vocabulary (the PascalCase `DirectoryPath`/`AbsolutePath`/`TargetFile`/`CommandLine`/`SearchPath` keys) and the permission tool names (`ask_permission`/`ask_question`) are reverse-engineered/UNVERIFIED (commented as such in the source). So currency rests on in-code breadcrumbs: `decode_ag_line` fires `drift::missing_field` on a tool-call missing its `name`, AND `drift::unknown_event` when a step carries `tool_calls` under a type that isn't `PLANNER_RESPONSE` (the rename signal — see the source). **Two-file layout:** the CLI writes BOTH `transcript.jsonl` (truncated) and `transcript_full.jsonl` (untruncated) per conversation in one logs dir with the SAME step stream, so **Antigravity's registry row** sets `path_filter: antigravity::admits_transcript` (read by `JsonlWatcher::new`; the `with_path_filter` builder exists only to override a row in tests) to watch only the canonical `transcript.jsonl` — else one conversation double-renders as two path-keyed `AgentId`s.
