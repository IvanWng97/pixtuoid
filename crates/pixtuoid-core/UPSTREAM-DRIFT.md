# pixtuoid-core — keeping the decode mapping current

Upstream wire contracts change without notice. The four defenses, and every source's watched surface.

Tool names, hook-event names and transcript types are upstream wire contracts that change **without notice** (the `Task`→`Agent` rename shipped undocumented). Four defenses, in order of reliability:

1. **Resilient detection (in code).** Prefer a *semantic* signal over a hardcoded name where one exists — e.g. `make_tool_detail` keys subagent dispatch on the stable `subagent_type` input field, not the tool name. This survives a rename by construction.
2. **Self-monitoring from the real stream (in code).** The decoders already see ground truth — and the breadcrumbs are now STRUCTURED: `source/drift.rs` (always-compiled) owns the four decode-drift breadcrumbs (`unknown_event`/`missing_field`/`unknown_dispatch`/`shape_drift`), each a `tracing::warn!` on the stable target `pixtuoid::drift`, so the warn-floor log and `pixtuoid doctor` surface them. An unrecognized `hook_event_name` VALUE → `unknown_event`, and an ABSENT `hook_event_name`/`session_id` KEY → `missing_field` (the two shared-arm bails are the whole hook plane's chokepoint — an upstream rename of either kills every hook event of every source riding them, and a plain `warn!` lands on a target `doctor::parse_drift_line` cannot see; undeduped is flood-safe on this plane, which carries only payloads we've committed to decoding, and the documented grok cross-fire is dropped quietly before them); a dispatch under an unknown name → `unknown_dispatch`; the `sessions/<pid>.json` registry consumer's once-per-run shape warn (#247 — the canonical instance of this defense for a NON-FETCHABLE surface defense #4 can't reach) → `shape_drift`. These surface drift the moment it appears in a user's own usage — no network, no upstream-layout dependency.
3. **Internal consistency test.** `every_registered_codex_event_decodes` / `every_registered_cc_event_decodes` (in `install/{codex,claude}.rs`) assert that every hook event we *register* has a decoder arm — catching the *registered-but-not-decoded* class (the original SubagentStop bug) at `cargo test` time.
4. **Upstream watch (CI).** `scripts/check_upstream_drift.py` + `.github/workflows/upstream-drift.yml` (weekly) read the names we depend on directly from our source and compare to live upstream; on a vanished name or a new unhandled Codex/Reasonix hook it opens a deduped `upstream-drift` issue. **A finding's DISPOSITION is load-bearing and the report keeps three apart**: a *verified change* (we read the surface that OWNS the name and it is gone → fix the decoder), a *review ping* (new upstream surface), and *probe health* (`blind` — a 404, a missing anchor, a parser that found nothing: all the script knows is that ITS OWN PROBE missed, so the affected checks are SKIPPED and the fix is to repin, never to edit a decoder). The report's H1 carries the disposition and IS the issue title — the workflow reads it back rather than keeping a second copy of those strings. Every document swept for name-presence declares an **anchor** in the script's `ANCHORS` table — ideally the declaration that owns those names, else one co-located with them (the table marks which grade each row is; a docs *page* can only ever be the weaker one) — and no anchor means no sweep. This is the #793 lesson: absence is only evidence of a rename if the owning declaration is still there. CodeWhale split `crates/tui/src/hooks.rs` into a module directory, the stale pin kept returning 200 as a `mod`/`pub use` facade, and the unanchored sweep reported three WORKING `DEEPSEEK_*` env vars as renamed under "decoder will silently drop events" — 5 of that report's 6 findings were false positives. **Adding a new swept document means adding its anchor** (an undeclared URL is reported as probe health and never swept) and a sample to the selftest's `ANCHOR_SAMPLES`, which tests the gate both ways: a pure upstream refactor yields probe health, an intact anchor still hands the body to the sweep. Those samples are hand-written to match, so they prove the GATE — never that an anchor is CORRECT against the live document; a typo'd anchor surfaces as a permanent weekly probe-health line. **Coverage is both EVENT/TYPE names AND payload FIELD names** — a renamed field is the same silent-failure class (the decoder reads `None`, the sprite quietly breaks), so beyond the event lists below the watch also checks the FIELD names each decoder reads wherever the upstream owner is fetchable: Reasonix payload json tags, Codex `EventMsg`/`ResponseItem` types + `FunctionCall` fields, CodeWhale `DEEPSEEK_*` env vars, opencode schema Struct fields, Copilot schema `properties`, OpenClaw hook-types fields, Hermes `_serialize_payload` keys (`agent/shell_hooks.py`). Each is ONE-DIRECTIONAL (only a VANISHED depended field alarms) and the field SETS are hardcoded literals next to the code (maintained by review, like `REASONIX_PAYLOAD_FIELDS` — a decoder scrape would drag in the defensive `KEYS` arrays + fixture JSON). **When you add/remove a wire field the decoder reads, update that source's `*_PAYLOAD_FIELDS` set** — the set is trusted to equal the decoder's reads (a stray member false-alarms on a field we don't depend on; a missing member silently loses coverage). Cursor + CC (closed binaries, docs-prose) and Antigravity (no fetchable schema) can't be field-watched — defense #2 is their limit. Sources:
   - **Codex** (open Rust): `codex-rs/protocol/src/protocol.rs` `HookEventName` enum (raw on `main`). `PreCompact`/`PostCompact` are intentionally omitted (`CODEX_KNOWN_OMITTED` in the script) — not agent activity. **Plus the ROLLOUT decode vocabulary** (#500): the transcript decoder's `("event_msg"|"response_item", …)` arms are registered NOWHERE, and its tail now BREADCRUMBS `drift::unknown_event` on an unrecognized OUTER `type` (one outside `codex::KNOWN_OUTERS` = a brand-new line SHAPE — the live-stream signal defense #4 can't see) while staying SILENT on an unhandled INNER under a KNOWN outer (a new `EventMsg`/`ResponseItem` variant we knowingly ignore — codex emits ~40/~15 of those and breadcrumbing each would flood). `read_codex_rollout_types` still diffs each depended INNER type against the `EventMsg` enum (protocol.rs) + the `ResponseItem` enum (`codex-rs/protocol/src/models.rs`) — one-directional (only a VANISHED depended type alarms). `task_started`/`task_complete` count via their `#[serde(alias="turn_started"/"turn_complete")]`.
   - **CC** (closed binary — no source to grep): the docs markdown `code.claude.com/docs/en/tools-reference.md` (authoritative tool-name list) **and `hooks.md`'s hook-event summary table** — diffed against `install/claude.rs` `EVENTS` (now incl. SubagentStart/SubagentStop, #241) + the script's `CC_KNOWN_OMITTED` set, so a registered event vanishing is a verified change and a NEW upstream event is a review ping. Tool names like `Agent` are NOT schematized upstream, so defense #2 is the real backstop for CC. **The TRANSCRIPT tail also breadcrumbs** (#763): `decode_cc_line` fires `drift::unknown_event` on a top-level `type` outside `claude_code::KNOWN_TYPES` (the ~18 current types — `user`/`assistant`/`attachment` decoded, the rest session-metadata sidecar lines — verified empirically against a live `~/.claude/projects` corpus, NOT a schema). It's the ONLY signal a new CC pseudo-type landed (the axis churns — `worktree-state`/`relocated`/`frame-link` are recent), and gets **NO CI drift-watch** (no fetchable transcript schema; defense-#2-only, the antigravity class). Guarded on the LOW-cardinality top-level `type` (session-freq) — NEVER the HIGH-cardinality inner `attachment.type` (`hook_success` streams ~per tool-call, would flood). `KNOWN_TYPES` is maintained by review against the live corpus, not a fetch — a new type surfaces as a breadcrumb in the warn-floor, add it there.
   - **Reasonix** (open Go): `internal/hook/hook.go` `Event` consts + the payload json tags (`event`/`cwd`/`toolName`/`toolArgs`/`subject`/`message`) on `main-v2`. `PostLLMCall`/`PreCompact`/`SubagentStop` are intentionally omitted (`REASONIX_KNOWN_OMITTED`).
   - **CodeWhale** (open Rust): `crates/tui/src/hooks/config.rs` `pub enum HookEvent` (snake_case wire names) on `main`, diffed against `install/codewhale.rs` `CODEWHALE_EVENTS` + `CODEWHALE_KNOWN_OMITTED`; the `DEEPSEEK_*` env-var check fetches its sibling `hooks/executor.rs` separately. (Both lived in a flat `crates/tui/src/hooks.rs` until upstream split it into a module directory — the old path still 200s as a `mod`/`pub use` shim, so a stale pin reads EMPTY rather than 404ing and reports every depended name as vanished, #793.)
   - **opencode** (open TS): the `EventV2` `type` literals in `packages/schema/src/v1/session.ts` + `packages/schema/src/permission.ts` on `dev` (the `main` branch was retired and the schema moved out of `packages/core/`, #406), diffed against the `match event` block in `source/opencode.rs`. ONE-DIRECTIONAL (opencode emits ~50 types, we map a handful) — only a VANISHED depended type alarms; `OPENCODE_TOLERATED` skips the defensive `permission.asked` alias.
   - **Copilot** (published JSON schema): the per-event `type` consts in the per-platform `@github/copilot-<os>-<arch>` (e.g. `copilot-linux-x64`) `schemas/session-events.schema.json` (served by unpkg, UNPINNED — follows the redirect to latest; the root `@github/copilot` is now a loader stub that 404s the schema, #406), diffed against the `match kind` block in `source/copilot.rs`. ONE-DIRECTIONAL like opencode (Copilot emits ~100 types, we map ~10) — only a VANISHED depended type alarms, so there is no `COPILOT_KNOWN_OMITTED` set. **Plus the NAMESPACE flood guard** (#763): the transcript tail now BREADCRUMBS `drift::unknown_event` on a `type` whose NAMESPACE (the family before the first `.`) is outside `copilot::KNOWN_NAMESPACES` (the complete 26-family `SessionEvent` set = a brand-new event FAMILY — the live-stream signal defense #4 can't see) while staying SILENT on a known-namespace event we ignore (copilot streams `assistant.*_delta`/`mcp.*` per token; breadcrumbing each would flood). `read_copilot_namespaces` diffs `KNOWN_NAMESPACES` against the live `SessionEvent.anyOf` union (`upstream_copilot_namespaces` — anyOf-scoped so nested-content tags like `audio`/`text` don't leak in as phantom families) — a NEW upstream namespace is a review ping BEFORE it floods.
   - **Cursor** (closed binary): the camelCase `hook_event_name`s on `cursor.com/docs/hooks`, diffed against `CURSOR_EVENTS` in `install/cursor.rs`. ONE-DIRECTIONAL (Cursor exposes ~18 hook events, we map ~5) — only a VANISHED depended event alarms; the common-word `stop` is low-confidence (the docs page contains the word regardless), so the distinctive `sessionStart`/`sessionEnd`/`preToolUse`/`postToolUse` carry the check.
   - **OpenClaw** (open TS): the hook-event types in `src/plugins/hook-types.ts` on `openclaw/openclaw` `main`, diffed against `OPENCLAW_EVENTS` in `install/openclaw.rs`. ONE-DIRECTIONAL (~40 upstream types, we register 6) — only a VANISHED registered event alarms.
   - **Hermes** (open Python): the shell-hook event KEYS of `_DEFAULT_PAYLOADS` in `hermes_cli/hooks.py` on `NousResearch/hermes-agent` `main` (the `hermes hooks test`/`doctor` fixtures, so a rename moves the key), diffed against `HERMES_EVENTS` in `install/hermes.rs`. ONE-DIRECTIONAL (~15 upstream shell-hook events, we register 4) — only a VANISHED registered event alarms.
   - **grok** (open Rust, `xai-org/grok-build`): THREE depended surfaces (`read_grok_events` + the transcript checks) — the hook events (`GROK_EVENTS` in `install/grok.rs`, read from `xai-grok-hooks/src/event.rs`; `GROK_KNOWN_OMITTED = {PreCompact, PostCompact}`), the ACP transcript xAI-extension vocabulary (`extensions/notification.rs` — a versioned protocol NOT fetched here, pinned UPSTREAM by grok-build's own `wire_tags` guard test, not ours), and the `active_sessions.json` liveness-registry struct. ONE-DIRECTIONAL — only a VANISHED depended name alarms. **Plus the METHOD flood guard** (#763): the transcript tail BREADCRUMBS `drift::unknown_event` on a top-level `method` outside `grok::KNOWN_METHODS` (`{session/update, _x.ai/session/update}` — a brand-new wire namespace = a structural change), staying SILENT on an unhandled `sessionUpdate` TAG under a known method (the high-cardinality axis — ACP chunk tags stream per token). **Plus the ACP-tag flood guard** (#766): the ACP-standard `session/update` decode moved to the shared `source/acp.rs`, whose tail breadcrumbs a `sessionUpdate` tag outside `acp::KNOWN_ACP_TAGS` (the latest v1 set, 13 tags) — a NEW ACP capability — while the per-token chunks stay silent. `KNOWN_ACP_TAGS` IS now drift-watched: `read_acp_tags` diffs it against the live v1 ACP schema (`ACP_V1_SCHEMA_URL` + its `unstable` twin, fetched as plain JSON — the "crates.io fetch" the deferral feared was unnecessary; the schema is a fetchable artifact), review-pinging a new upstream tag before it floods. v2 is a separate line grok doesn't speak → not fetched.
   - **omp** (open TS, `can1357/oh-my-pi`): TRANSCRIPT-ONLY — the entry `type` discriminators (`read_omp_entry_types` vs `source/omp.rs`'s `match kind`) + the entry/message FIELD sets (`OMP_SESSION_ENTRY_FIELDS`, `OMP_MESSAGE_FIELDS`), diffed one-directional like copilot (omp emits more types than we map — only a VANISHED depended type/field alarms). **Plus the entry-TYPE flood guard** (#763): the tail BREADCRUMBS `drift::unknown_event` on an entry `type` outside `omp::KNOWN_ENTRY_TYPES` (the complete `RawFileEntry` set = a brand-new entry SHAPE), staying SILENT on a known type we ignore AND on the unbounded nested `customType` axis (extension-authored — the true flood axis). `read_omp_known_types` diffs `KNOWN_ENTRY_TYPES` against the live `session-entries.ts` literals (`upstream_omp_entry_types`, which resolves the `type: typeof CONST` title slots) — a NEW upstream type is a review ping BEFORE it floods. **Plus the SESSIONS-DIR surface**, whose blast radius is the whole office rather than one entry type: `OMP_DIRS_*` reads `packages/utils/src/dirs.ts` for the five directory env vars, and `OMP_ENV_*` reads `packages/utils/src/env.ts` for the `.env` overlay that can move that same dir — split BY ROLE (`OMP_ENV_LOCATORS` = where the files come from and when the resolver rebuilds; `OMP_ENV_PARSERS` = what one line means) so each message names the half a maintainer edits. Both are name-presence sweeps over COMMENT-STRIPPED source, because `env.ts` names those very functions in its own JSDoc.
   - **Antigravity** is deliberately **defense-#2-ONLY** — NO drift-watch row (defense #4). It's a closed Google IDE, and while its on-disk `transcript.jsonl` wire IS partially observable (a Google Cloud Community tutorial + the confirmed on-disk path `~/.gemini/antigravity-cli/brain/<id>/.system_generated/logs/` quote real lines: field set `{step_index, source, type, status, created_at, content, tool_calls}`, step types incl. `USER_INPUT`/`PLANNER_RESPONSE`/`SEARCH_WEB`), that is illustrative SAMPLE wire, not a stable published schema — so it is NOT a reliable `check_upstream_drift.py` source (same NON-FETCHABLE-SCHEMA class as the CC `sessions/<pid>.json` registry, #247; do NOT add a reader — there is nothing stable to fetch). Only `query` (the `search_web` arg) is capture-confirmed; the rest of `decode_ag_line`'s tool-arg vocabulary (the PascalCase `DirectoryPath`/`AbsolutePath`/`TargetFile`/`CommandLine`/`SearchPath` keys) and the permission tool names (`ask_permission`/`ask_question`) are reverse-engineered/UNVERIFIED (commented as such in the source). So currency rests on in-code breadcrumbs: `decode_ag_line` fires `drift::missing_field` on a tool-call missing its `name`, AND `drift::unknown_event` when a step carries `tool_calls` under a type that isn't `PLANNER_RESPONSE` (the rename signal — see the source). **Two-file layout:** the CLI writes BOTH `transcript.jsonl` (truncated) and `transcript_full.jsonl` (untruncated) per conversation in one logs dir with the SAME step stream, so **Antigravity's registry row** sets `path_filter: antigravity::admits_transcript` (read by `JsonlWatcher::new`; the `with_path_filter` builder exists only to override a row in tests) to watch only the canonical `transcript.jsonl` — else one conversation double-renders as two path-keyed `AgentId`s.
