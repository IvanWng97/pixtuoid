# pixtuoid-core — where to look

Answers for the questions indexed in [`CLAUDE.md`](CLAUDE.md)'s
"Where to look". An entry earns its place only when landing on the
obvious symbol does NOT answer the question — it names a seam, a
split, a chokepoint, or a decision that looks like a bug. Everything
else is the code's job to prove.

- "How does the per-agent state machine work?" → **two stacked layers, both extracted so the reducer reads as a coordinator.** Layer A = `state/fsm.rs` (single-slot transitions); Layer B = `state/scope.rs` (the parent↔subagent tree). Cross-slot correlation (`active_tasks` suppression, permission gating, hook-wins dedup) is NOT the FSM: bookkeeping in `state/correlation.rs`, DECISIONS in `state/reducer/mod.rs`. Don't move the correlation maps onto `AgentSlot`.
- "How does multi-source decoding work?" → `JsonlWatcher` takes decoder/deriver FN POINTERS (don't trait-ify the uniform signatures); defaults come from the source's REGISTRY ROW (`source/registry.rs`), the single source of per-CLI cross-cutting truth; per-source wire knowledge lives in that source's module + fixtures. The display last-mile is CENTRALIZED in `decoder.rs` — route any new content→display string through it. CLI attribution comes ONLY from the shim-owned `_pixtuoid_source` key, never the public `source` field (CC overloads it — the ghost-split trap; WHY at `decode_hook_payload`).
- "How does the model flame (burn tier) get its data?" → `AgentEvent::ModelInfo` carries RAW wire strings — interpret-at-paint (`pixtuoid-scene::burn`). CC has TWO effort channels: hook `effort.level` (primary) and transcript ultra-markers (decoder-synthesized; the `ultra_effort_exit` twin kills the flame via last-seen-wins — the TTL only backstops a missed exit). Unknown id = no-op on BOTH transports.
- "How does the token meter (the desk paper tower) get its data?" → `AgentEvent::Usage { fresh_tokens }` is a per-reading FRESH-spend delta (cache reads excluded at decode); interpret-at-paint, JSONL-only. The trap: Codex's reading is the per-turn `last_token_usage`, NEVER the cumulative twin, and codex `input` INCLUDES the cached share. A late attach counts only post-attach burn (#204) — don't "fix" by replaying the backlog.
- "How does focus-jump resolve the agent's pid?" → the shim stamps `_pid` via an ancestor WALK past interposed shells; the daemon stamps `PidIdentity` (pid + kernel start marker) and the click REFUSES a recycled/dead pid (#527). WHICH channel a source rides is the registry's `FocusChannel` (DATA-only, wasm-compilable); `TranscriptProbe` sources are never stamped — a stale stamp would shadow their probes. Every platform WALKS rather than trusting a raw ppid (#528/#896); what saves an unlisted interposer is the WALK, not the marker.
- "Why don't old idle sessions show on startup?" → `source::jsonl::walk::should_seed_at_eof`, the first-sight gate. The full ladder (activity clock vs mtime, vouches, negative vouch, instant exit) is a family of entries in [`SHARP-EDGES.md`](SHARP-EDGES.md) — grep "first-sight gate".
