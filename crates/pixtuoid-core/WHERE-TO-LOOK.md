# pixtuoid-core — where to look

Answers for the questions indexed in [`CLAUDE.md`](CLAUDE.md)'s
"Where to look". An entry earns its place only when landing on the
obvious symbol does NOT answer the question — it names a seam, a
split, a chokepoint, or a decision that looks like a bug. Everything
else is the code's job to prove.

- "How does the per-agent state machine work?" → **two stacked layers, both extracted so the reducer reads as a coordinator.** Layer A = `state/fsm.rs` (single-slot transitions, each unit-tested); Layer B = `state/scope.rs` (the parent↔subagent tree ops). Cross-slot correlation (`active_tasks` suppression, permission gating, hook-wins dedup) stays in the reducer's layer — it spans slots and is NOT the FSM; the seven correlation maps' bookkeeping lives in `state/correlation.rs` (a `Correlation` struct the reducer owns), the DECISIONS stay in `state/reducer/mod.rs`. Don't move the correlation maps onto `AgentSlot`. Gate-aware suppress-restore is pinned by `suppressed_child_event_keeps_parents_own_parallel_tool_gate`.
- "Why is the subagent's sprite the right one and not the parent?" → `reducer::Reducer::apply` does subagent-leak suppression via `active_tasks` before applying. `claude_code::decode_cc_line` emits `AgentEvent::Rename` from `attributionAgent`.
- "How does multi-source decoding work?" → `JsonlWatcher` takes `LineDecoder`/`LabelDeriver`/`IdDeriver` fn pointers (Strategy via fn pointers, not traits — don't trait-ify the uniform signatures); the defaults come from the source's REGISTRY ROW (`source/registry.rs`), which is the single source of per-CLI cross-cutting truth: label prefix, hook id-key/custom decoder, the `Transcript{line_decoder, id_from_path, path_filter, cwd_extractor}` bundle (absent capability is TYPED — hook-only rows carry `transcript: None`), reducer capability flags (`SourceCaps`), and `verified_version`. Per-source wire knowledge lives in that source's own module (`source/<cli>.rs` + its `native.rs` runtime half) and is pinned by the sanitized live-capture fixtures under `tests/sources/fixtures/<name>/` — read the module and its fixtures, not a summary. The drift-prone display last-mile is CENTRALIZED in `decoder.rs` (cap policy, `display_safe` terminal egress, cwd-label rule): a new content→display string must route through those chokepoints, never restate the policy. CLI attribution comes ONLY from the shim-owned `_pixtuoid_source` key, never the public `source` field (CC overloads it for the start reason — the ghost-split trap; WHY at `decode_hook_payload`). `AgentId::from_parts(source, key)` namespaces ids per source. Adding a CLI: follow the checklist in [`CONTRIBUTING.md`](../../docs/CONTRIBUTING.md#adding-a-new-agent-cli) (root `CLAUDE.md` "When refactoring" summarizes it) — the checklist steps with test teeth (registry row, fixtures, sources.json bridge, badge hue, the two binary integration goldens) fail loudly; run full `just preflight`, not `-p <crate> --lib` (#692's lesson).
- "How does the model flame (burn tier) get its data?" → `AgentEvent::ModelInfo { model, effort }` carries RAW wire strings — interpret-at-paint, the tier tables live in `pixtuoid-scene::burn`. CC has TWO effort channels: the hook payloads' documented `effort.level` (the PRIMARY, decoded in the shared arms) and the transcript's periodic ultra/ultrathink markers (no wire value → decoder-synthesized; the `ultra_effort_exit` twin synthesizes the non-max `ULTRA_EXIT_LABEL` so last-seen-wins kills the flame instantly — the TTL only backstops a missed exit, and `burn::fresh_effort` display-suppresses the sentinel). The reducer caches `slot.model` (last-seen-wins, a mid-session `/model` switch tracks) + `slot.effort: EffortObservation{value, seen_at}` — the scene's `EFFORT_TTL_SECS` turns Codex's per-turn field and CC's periodic marker into ONE freshness semantic. Unknown id = no-op on BOTH transports (wire data, not liveness). Per-source wires live in each decoder; bounded residual: a replayed-from-top transcript reads a historical effort marker as fresh for up to the TTL after attach — cosmetic, accepted.
- "How does the token meter (the desk paper tower) get its data?" → `AgentEvent::Usage { fresh_tokens }` carries a per-reading FRESH-spend delta (cache READS — ~95% of the raw total — are excluded at decode). Posture mirrors ModelInfo: interpret-at-paint (`pixtuoid-scene::token_meter`), unknown id = no-op, counters-only in the reducer (`tokens_used` saturating + `last_usage: Option<UsageObservation>` — a half-stamped reading unrepresentable). JSONL-only — no hook carries usage, so it never enters the hook-wins dedup. Per-source arithmetic lives in each decoder + its fixture test; the one trap worth naming: Codex's reading is the per-turn `last_token_usage`, NEVER the cumulative `total_token_usage` twin (the reducer accumulates deltas), and codex `input` INCLUDES the cached share (fresh = input − cached, saturating). Flash-safety is the PAINTER's exiting filter, not event order. Deliberate attach residual: an oversized (>1 MiB) in-flight transcript first-sights with no backlog replay (#204), so a late attach counts only post-attach burn — do not "fix" by replaying the backlog (N×10 MB reads at boot; the #632 live dogfood is the record).
- "How does focus-jump resolve the agent's pid?" → the shim fills `_pid` (an ancestor WALK past the runner's interposed shell — `cli_pid` over `INTERPOSER_SHELLS`; a parent already gone yields NO stamp) when absent; opencode's plugin and CodeWhale's env-mode stamps win. The daemon peeks `_pid` UNCONDITIONALLY (an exit-watch init failure must not take the focus cache down) and stamps `PidIdentity` — pid + the kernel start MARKER, EQUALITY-only — onto the batch's Identity events; the click re-reads the marker and REFUSES a recycled/dead pid (#527; markerless stamps skip the check, additive). WHICH channel a source rides is the registry's `FocusChannel` capability — the ONE data-driven truth shared by the stamp gate, `focus::resolve_pid`, and doctor; DATA-only so the table compiles to wasm (native probe fns pinned by `transcript_probe_sources_all_have_a_resolve_arm`). `TranscriptProbe` sources (CC/Codex/grok) are never stamped — a stale stamp would shadow their recycle-guarded probes. Every platform WALKS rather than trusting a raw ppid (#528/#896). Two limits, stated exactly because the obvious phrasing of each is wrong: an unlisted interposer shell still stamps a transient pid, and what saves it is the WALK (a dead pid owns no window → not focusable), NOT the marker — don't restate as "the marker refuses it" (a Windows handle stays valid after termination; the marker earns only the RECYCLED-pid half). Two residuals neither half catches: a markerless stamp is cached unguarded, and a parent recycled between the shim's snapshot and the daemon's read matches itself.
- "Why don't old idle sessions show on startup?" → `source::jsonl::walk::should_seed_at_eof`, the first-sight gate inside `walk_jsonl` — mtime/activity outside 1h OR a structural end marker parks the cursor at EOF with no `SessionStart`, on every first-sight path. The full ladder (activity clock vs mtime, probe vouches, negative vouch, instant exit) is a family of entries in [`SHARP-EDGES.md`](SHARP-EDGES.md) — grep "first-sight gate".
