# pixtuoid-scene — where to look

Answers for the questions indexed in [`CLAUDE.md`](CLAUDE.md)'s
"Where to look". An entry earns its place only when landing on the
obvious symbol does NOT answer the question — it names a seam, a
split, a chokepoint, or a decision that looks like a bug. Everything
else is the code's job to prove.

- "Where does a furniture's footprint / visual size / approach side / dwell come from?" → **`layout::decor`** — ONE geometry table: `FurnitureDef` keyed by the unified `Furniture` enum (+ `desk_furniture_def()` for the per-agent home desk). The role enums (`WaypointKind`, `PodDecor`, `PlantKind`, `WallDecor`) carry NO dimensions — each maps `.furniture()` onto one row, so an item playing two roles has its shape defined once. Four load-bearing distinctions: `footprint` (blocked ground) ≠ `visual` (sprite, may overhang — the occlusion sharp edge); `occupies_pos` (render fact) ≠ `exclusive` (capacity fact); placement overlap (bug, swept) ≠ occlusion overlap (correct, z-sort resolves it); `dwell` is orthogonal. A NEW `WaypointKind` must also join or opt out of the snapshot example's vocabulary census (compile-enforced).
- "Why doesn't a bigger buffer just render the office sharper?" → `render_scale.rs` is THE layout-space ↔ buffer-space seam; `floor_capacity_is_invariant_under_render_scale` pins the property and `without_the_seam_a_bigger_buffer_builds_a_bigger_office` is the negative control keeping its teeth.
- "How is the office laid out?" → `layout::SceneLayout::compute_with_seed` coordinates private helpers. The desk count is UNCAPPED in production: `max_desks: None` fills the buffer; `Some(n)` is the deterministic test/golden knob (`TEST_DEFAULT_DESKS = 16` is only the named test default, not a limit).
- "How does walk-pace physics work?" → `pixtuoid_scene::physics` (pure) freezes a per-leg `WalkProfile`; the stateful timeline consuming the profiles is the sibling `motion` module (the render authority). Per-agent personality comes from disjoint splitmix64 bit slices.
- "Which side does an agent approach furniture from?" → `layout::approach_point` (`layout/approach.rs`) is **A\*'s goal**: the side nearest the agent's home desk, filtered by `FurnitureDef.approach` (rotated by facing) AND `ReachSet` reachability. Seat kinds add a post-A\* SETTLE onto `seated_foot_cell` so the sprite glides onto the seat pop-free — don't collapse the settle back into a single `pos` target; an unapproachable seat returns the blocked `pos` as a sentinel and the caller SKIPS it this cycle. Every desk-touching leg (entry/wander/exit/snap-back) shares `pose::desk_leg_endpoint` — router goal = `desk_approach_cell`, chair = settle target, NEVER the raw router goal (a blocked goal snaps to the corridor front and the agent walks THROUGH the desk). Which side a chair lands on is a per-desk layout fact (`layout.desk_facing_at`). Seating a desk EAST/WEST touches exactly three places — `desk_walk_anchor_facing`, `Seat::view`'s fused arm (+ `sprite_for`), and the placer emitting the facing; everything else is already facing-derived. Pinned by `desk_entry_routes_around_the_desk_then_settles_onto_the_chair` + `wander_legs_approach_the_desk_via_an_allowed_side_not_through_the_front`.
- "How is the office rendered (pixel pass)?" → `pixel_painter::render_to_rgb_buffer` = `sim_step` (advance the world, no pixels) then the paint pass over `&SimFrame`. Three different outputs sit over this one world render: the tui half-block flush, the floating window's downscale-then-upscale surface, and the snapshot example's `TestBackend` PNG.
- "How do agent name-badge labels work (the `cc·1a2b` text above each character)?" → the MODEL is `overlay::build_overlay`; it carries TONE, not color, and every painter renders the same split (marker in `label_tone_rgb`, name in the per-CLI badge hue). The wasm painter exports the model as JSON and the site lays DOM spans over the canvas — baked AA text would upscale blocky.
- "How do the room dividers render (frosted-glass partitions)?" → render half in `pixel_painter/wall.rs`, geometry half in `layout::rooms::walls` — bound by shared consts (`WALL_THICK_H/V` define both the mask footprint and the painted face; they silently diverged once, #559) and the shared `stitch_vertical_wall` (mask and painter stamp the SAME stitched rect, so blocked ground and drawn glass can't drift). Door jambs draw from `SceneLayout.doorways` — the wall resolver hands its cut openings to the renderer; the painter never re-infers gaps.
- "How does the theme system work?" → `theme/mod.rs`; the guard suite is the part grep won't surface: `source_colors_cover_every_registered_source` pins the field set to the source registry (a new source forces a new field per theme), the legibility guards enforce minimum hue distances, and `tests/site_badge_colors.rs` pins the site's copies. The [t] picker UI is the binary's; `set_theme()` flushes the `FrameCache`.
- "How does weather work?" → weather is an ATMOSPHERE, not a light level: `sky::atmo(weather)` is a pure transmission model and brightness = `emitter_lum × atmo`, so it stays altitude-coupled (a stormy noon out-lights a stormy dusk). `pixel_painter::force_weather` is the single chokepoint every derivation funnels through (snapshot's `--weather`; production never sets it).
- "How does the sun/moon sky-light work?" → `sky::emitter(now) -> SkyState` is the ONE physical light source; `time_of_day_look`, `beam_strength`, and `sun_on_wall` all derive from the same `SkyState` + `Atmo` pair — one shared azimuth/altitude is why disc position, floor spill, and wall sun-spot can never disagree. Disc placement + night stars: `background/celestial.rs`.
- "How does the meeting room come alive (sitting + group talk)?" → per-room seats are ordinary waypoints (idle agents arrive emergently, no coordinator; single-occupancy rides the SpotClaims sharp edge). `chitchat` is venue-keyed: a room's slots merge into ONE conversation (`VenueKey::Room`); the lounge couch collapses via `venue_wp_idx` instead of overloading `room_id`. A pack lacking `side_seated` degrades to front `seated`, never an invisible sitter.
- "How does per-agent motion state work?" → `motion::MotionState`: entry/exit/snap-back legs (`WalkLeg` carries `from` so walks start where the sprite actually is), `walk_path` (frozen geometry; profiles freeze duration), and the `wander: WanderState` phase machine. Owned per floor by `FloorCtx.motion`.
- "What is the elastic wander timeline?" → `advance_wander()` in `motion/mod.rs`; two don'ts grep won't warn you about: the stale-resume trigger is a frame-cadence sentinel — do NOT raise it to "max dwell" (off-screen gaps would replay the backlog); and the `WanderPhase::Seated` arm returns `Pose::SeatedIdle` DIRECTLY — don't "simplify" it back to the stateless `idle_pose` fallthrough, whose independent timeline drifts (a teleport).
- "How does the gateway mascot (the OpenClaw lobster) work?" → `creatures.rs`; ONE mascot per daemon INSTANCE (the wander seed folds source AND instance so two gateways diverge; presences project onto the ground floor only). Destinations come from the WHOLE walkable floor (`walkable_target`) — the curated per-furniture list WAS the crowding (pigeonhole; measured, deleted) and `four_gateways_rarely_crowd_now_that_the_whole_floor_is_in_play` pins against a return. Given up deliberately: destinations no longer encode daemon state (the CADENCE + tint do), and a mascot may rest in open floor — don't re-add claim/probe machinery, it would couple one mascot's motion to which siblings exist. The sim NEVER moves a returned point for sprite size — that's the painter's `keep_sprite_on_canvas` (the #912 sharp edge).
- "How does the lofi soundtrack get composed and rendered (and how do I add an instrument / a stem)?" → `audio/compose.rs::compose(mood, seed)` → `audio/synth.rs::gen_beds` through the same cores the frozen fingerprint anchors pin. A new instrument = the 5-step checklist in `.claude/skills/procedural-lofi`; a new STEM is an arc spanning `LoopStem` (Rain stays LAST) / `TRACK_STEMS` / `StemLevels` / `lane_recipe` + `gen_bed` arm (mind the silent `_ => Vec::new()` fallback) / the length asserts / audition arrays / the wasm+site gain-node counts. Quality gate is statistical: blind-audition a seed batch, ratify the GENERATOR.
